# 本项目多代理指导（Sol 领导 + Luna 按会话启用）

## 角色分工

- **主会话（Sol / 当前会话模型）**：理解需求、拆解任务、处理冲突、最终整合与验收；保留 commit、PR 和部署控制权。
- **luna_scout**：只读探索代码库、依赖、日志和文档。
- **luna_worker**：在明确范围内完成有界实现。
- **luna_critic**：独立审查正确性、安全、回归风险和测试缺口。
- **luna_tester**：运行指定验证并报告证据。

## 指导原则

- Luna 默认关闭；只有用户在当前会话明确要求使用 Luna 时才允许委派，该同意不延续到后续会话。
- Luna 候选由用户在共享 provider 的 `luna-models.json` 中有序维护；第一项是默认模型，第二项是套餐额度备选。Sol 使用当前主会话模型，不进入该列表。
- 委派应目标单一、边界清晰、可独立验证；信息不足、越界、冲突或低置信度时回到 Sol 决策。
- 自动编码的一个内聚场景由同一 worker 保持完整，不把测试驱动循环拆给多个执行者。
- 并行委派不得具有重叠写入范围；Luna 不得 commit、push、创建 PR、部署或扩大授权。
- 具体命令、参数、任务卡格式、后端路由与返回契约由共享 Sol-Luna provider 及调用方适配器维护，不在本指导文件复制执行过程。
