# Claude Code 多代理政策

- 主会话使用最强可用模型（领导层）：规划、审核、整合、兜底。
- 执行层调用 `.claude/agents/` 下稳定命名的 `luna-*` 角色；模型由 Sol-Luna 控制器选择。
- Sol 在调用 Luna 前必须规划具体任务卡：单一目标、允许范围、禁止范围、约束、预期输出和验证证据；六项各占一行，严格使用 `字段：非空内容`，任一项不清楚时不得委派。
- Luna 委派必须是单一可观察目标、短响应、可独立验证的小闭环；探索、测试和审查分别调用。自动编码实施时，一个完整内聚场景组由同一 worker 完成，禁止拆分 RED、GREEN、REFACTOR；跨模块场景只有在写入与验证边界明确且任务卡可保真表达时才可委派。
- **建议优先利用空闲子 Agent 卡槽**：若当前波次有多个已满足依赖且彼此隔离的独立场景组，Sol 应尽量并行
  调度可用卡槽，保留领导、协调、证据验收、冲突处理和最终决策职责；不得为填槽拆分内聚场景或 TDD，
  无法证明安全并行时保持串行。
- **建议任务不清晰时及时回问 Sol**：Luna 发现目标、上下文、范围、依赖、约束或验收证据不明确，或发现
  冲突、越界风险时，立即暂停并向 Sol 提出具体问题；不要猜测或先执行可能扩大范围的修改。
- 角色责任、委派、卡槽调度、升级或协作复盘可参考 `method-router/management-collaboration/SKILL.md` 的
  RACI、委派任务卡、Kanban/WIP、时间盒和检查点；该方法论不替代项目生命周期、用户授权或 Git 边界。
- Luna 默认开启并使用 `mode=auto`；有效配置为 `off`，或用户在当前任务说“不用 Luna”“只用 Sol”时，禁止调用 Luna。Luna 候选由用户在共享 provider 的 `luna-models.json` 中维护；第一项是默认模型，第二项是套餐额度备选，`auto` / `default` 均选择第一项，也可按模型 ID 或别名显式选择。Sol 使用当前主会话模型，不进入该列表。Codex 候选遵循共享适配器声明的原生优先原则；原生不适用时只能在任务启动前通过兼容通道执行同一精确模型。用户要求 `native only` 时不可降级，任何路径都不得静默换模，已启动任务不得跨通道自动重跑。具体 runner、命令和能力探测由共享 provider 契约与调用方适配器维护，不在本指导文件重复。
- 只有用户明确要求项目级或全局持久切换时，才修改 `mode` / `model` 配置。
- `run` / `smoke` 在 `auto` / `force` 下无需额外标志；`--user-triggered` 仅用于当前用户明确要求 Luna 时单次覆盖有效 `off`，不得持久化该覆盖。
- 调用 Claude Code 时使用所选列表项的 `claude_model`，由用户级 `modelOverrides` 将 `override_model` 路由到 `provider_model`，并检查 JSON `modelUsage` 是否与预期 provider 模型一致。
- 当前上下文窗口按真实证据使用 200k；不得虚报 `[1m]` 或关闭未知模型窗口保护。
- 失败或质量不达标立即 escalate 回主会话。
- commit / PR / 部署永远由主会话控制。
