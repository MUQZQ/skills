# 调度计划

## task 与 worker 调度单元

- T1、T2、T3 保持为现有任务系统中的三个 tracker task。它们仍是唯一的持久状态、依赖与独立验收单元，不改变编号和粒度。
- worker 的执行单元不是单个微任务，而是本轮临时计算的场景组。场景组只用于调度，不落盘为第二套任务状态，也不拥有 task 的完成判定。

## 分组决定

将 T1、T2、T3 合并为一个临时场景组 `登录锁定闭环`，交给同一个 bounded worker 连续完成。理由是三项任务服务同一可观察场景、写入同一认证模块、共享同一 fixture 与测试进程，且只有组合后才产生完整价值；合组可减少重复上下文加载、fixture 准备和重复测试成本。当前也不存在独立审批、发布、回滚、迁移或可隔离并行收益等拆组边界。

## 组内顺序

1. T1：先增加并运行登录锁定的失败测试，建立有效 RED，并确认失败来自锁定计数行为尚未实现。
2. T2：在同一 worker、同一上下文中实现最小计数器逻辑，运行相关测试直到 GREEN。
3. T3：补充审计事件断言，复跑完整登录锁定场景；必要整理后再次复跑同一组测试。

RED、GREEN、REFACTOR 属于这个场景组内的一条连续 TDD 闭环，不为每个阶段或每个微任务分别启动 worker。

## 验收与状态更新

worker 返回组级结果时，必须同时提供 T1、T2、T3 各自的 diff 映射、测试命令、结果和验收证据，以及完整登录锁定场景的组级证据。协调者核对共享工作树的真实 diff、允许写入范围和测试结果后，按 task 逐项更新唯一 tracker：

- T1 仅在有效 RED 证据可归属时更新；
- T2 仅在计数器行为和直接测试通过时更新；
- T3 仅在审计事件断言及完整场景通过时更新。

不得因为场景组返回 `DONE` 就一键完成 T1、T2、T3。若只有部分 task 达标，只更新已验收项；其余 task 保持未完成，并依据当前 diff 与证据重新调度。
