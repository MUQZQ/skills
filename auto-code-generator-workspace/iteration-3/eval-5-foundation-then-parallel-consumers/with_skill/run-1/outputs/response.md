# 调度计划（auto-code-generator v4.2）

## 场景组划分

- `G1-foundation`：仅包含 T1，目标是定义公共接口并用契约测试锁定行为。公共契约是两个消费者的共同前置，也具有独立的变更和验收边界，因此不与消费者放入同一 worker。
- `G2-package-a`：仅包含 T2，在 package-a 接入已经验收的接口。
- `G3-package-b`：仅包含 T3，在 package-b 接入已经验收的接口。

T1、T2、T3 仍是任务系统中的持久状态与逐项验收单元；上述场景组只是当前波次的临时 worker 调度视图，不复制任务状态。

## 依赖波次

1. 第一波只调度 `G1-foundation`。worker 完成 T1 的接口实现和契约测试后，协调者核对真实 diff、允许写入范围、契约测试命令与结果，并逐项验收 T1。
2. 只有协调者已验收 T1、权威 tracker 将其标为完成后，第二波才调度 `G2-package-a` 和 `G3-package-b`。
3. 不在 T1 尚未验收时提前启动消费者，也不把 T1、T2、T3 全部交给一个 worker，以免公共契约变化与消费者实现互相掩盖证据。

## 并行条件

T2 与 T3 分别使用独立场景组并行，前提是调度前再次确认：

- package-a 与 package-b 的实际写入文件和生成输出不重叠；
- 不竞争共享独占资源，也不同时修改 manifest、依赖声明或公共接口；
- 两组只消费已经验收的 T1 契约，不再各自演进该契约；
- 聚焦测试、diff 和失败证据能分别归属于 T2、T3。

任何一项隔离条件无法证明时，两组改为串行。

## 验收与失败恢复

- 协调者分别检查 T2、T3 的实际 diff、聚焦测试和任务验收标准，只更新证据充分的底层 task；并行波次结束不等于两项任务自动完成。
- 若 T2 失败或越界，只冻结并恢复 `G2-package-a`，保留现场并由协调者按当前 diff 重划该组；已验收的 `G1-foundation` 不回退，隔离条件仍成立且证据完整的 `G3-package-b` 也不受牵连。
- T3 失败时同理。只有失败揭示 T1 公共契约本身错误，才升级为协调问题，重新打开受影响依赖并停止消费者波次，而不是静默回退全部改动。
