# 调度计划（auto-code-generator v4.1 快照）

## 调度单元划分

旧版规则没有独立的“临时场景组”层，直接以 tracker task 作为 bounded worker 调度和验收单元：

- T1：一个独立 worker 定义公共接口并添加契约测试；
- T2：一个独立 worker 在 package-a 接入；
- T3：一个独立 worker 在 package-b 接入。

## 依赖波次

1. 第一波仅执行 T1。worker 返回后，协调者核对真实 diff、允许写入范围、契约测试命令与结果；证据支持 `DONE` 后才更新 T1 的唯一任务状态。
2. T1 状态确认完成后，T2 与 T3 才成为依赖就绪任务并进入第二波；T1 未验收时不提前启动消费者。

## 并行条件

T2 与 T3 可以并行，但要在调度时证明：

- 实际写入文件和生成输出不重叠；
- 不竞争共享独占资源；
- 不再同时演进 T1 定义的公共契约、manifest 或依赖声明；
- 不消费尚未落地的接口；
- 聚焦测试和变更证据可分别归属于 T2、T3。

无法证明这些条件时，使用独立 worker 串行执行。

## 验收与失败恢复

- 协调者分别核对 T2、T3 的实际 diff、测试命令与结果、需求和范围，证据支持后才逐项更新任务状态。
- 任一消费者发生越界或并行重叠时，冻结相关任务并保留已有改动；协调者检查组合状态后重划边界并串行恢复，不自动覆盖或清理改动。
- 例如 T2 单独失败且没有污染共享契约或 T3 范围时，只恢复 T2；T1 已经完成的状态不因消费者局部失败自动回退。若失败暴露公共接口缺陷，则需要协调者重新判断 T1 及其依赖状态。
