依据 v4.2（R6、3.2、3.3、3.6、错误恢复表、Stage 1），T1 是公共契约，命中“公共基础契约及其多个消费者”强制拆分边界，必须独立成组。

**场景组**：G1={T1}（基础组）；G2={T2}；G3={T3}。T2/T3 不得与 T1 合组；组是临时调度单元，不落盘为第二状态源（R12）。

**依赖波次**：波次1 仅 G1；协调者验收 G1 后，G2、G3 才进入波次2（“基础先独立成组，验收后消费者再分别调度”）。

**并行条件（G2/G3）**：题设“写入与测试完全隔离”不等于可直接并行，须同时满足五项隔离——写入文件/生成输出不重叠；不竞争独占资源；不同时演进同一公共契约、migration、manifest 或依赖声明（若 T2/T3 都要改同一依赖声明/manifest 则不并行，先核实）；不消费对方未落地接口；聚焦测试与证据可分别归属。任一不满足即串行。

**验收**：组完成≠task 完成；协调者逐项核对真实 diff、allowed_writes、聚焦测试命令/结果后，逐 task 更新状态；T1 未验收不得启动 T2/T3。

**失败恢复**：G1 失败→重做 G1，T2/T3 冻结不入队；G2/G3 并行中意外重叠→冻结并发集合、保留改动、协调者检查组合状态后重划；单个 task 失败→只更新合格项，失败项按当前 diff 重划，禁止一键完成或自动回退。

**暂停条件**：baseline 漂移（输出 BASELINE_CHANGED）、权威生命周期/schema 不明、任务边界不明、Critical/Important 未解决、真实阻塞、缺关键证据。

**第一个实质动作**：Stage 1 只读取证——读项目规则与实时生命周期状态、当前分支、HEAD、status、baseline；不改文件、不更新任务状态、不执行 Git mutation；输出所有权决定句“由谁管理生命周期，本 skill 仅负责调度范围”。证据不足则先报缺失项再规划。
