# 设计领域路由器

## 定位

本 Skill 只负责识别设计产物、判断实施阶段、选择主 Skill 和说明路由理由。
具体设计知识、工具步骤、实现方式和验证细则全部由被选中的 Skill 负责。

系统或产品问题定义、架构决策与重构方法进入 `method-router`；视觉、交互、图示或办公文档产物明确时由 `design` 直接路由。
两者职责互斥，不互相循环调用。

## 路由规则

| 规则 | 内容 |
|------|------|
| R0 | 用户显式指定具体 Skill 时直接服从 |
| R1 | 每个任务只选择一个主 Skill |
| R2 | 仅当辅助 Skill 职责不重叠且确有必要时，最多补充一个辅助 Skill |
| R3 | 父 Skill 不复制叶子 Skill 的工作流、知识清单或验证细则 |
| R4 | 不建立第二套生命周期、任务状态或 Git 权限 |
| R5 | 路由后必须说明产物、阶段、主 Skill 和选择理由 |

## 主路由映射

| 主 Skill | 适用边界 |
|-----------|----------|
| `ui-ux-pro-max` | UI/UX 知识检索、评审、设计系统建议与实现指导；不直接负责项目文件修改 |
| `frontend-design` | 创建或修改实际前端界面、页面与组件 |
| `drawio-skill` | 流程图、架构图、UML、ER 与 Draw.io 产物 |
| `visualize:visualize` | 对话内交互式可视化、图表、模拟器与解释工具 |
| `presentations:Presentations` / `documents:documents` / `pdf:pdf` | 对应办公文档产物 |

## 裁决顺序

1. 用户显式指定具体 Skill 时直接使用。
2. 未显式指定时，先判断需求是否已经形成明确设计产物。
3. 系统或产品问题定义、架构决策与重构方法交给 `method-router`。
4. 视觉、交互、图示或办公文档产物明确时，根据主路由映射选择一个主 Skill。
5. 只执行所选主 Skill 的验收合同，不在父路由重复叶子规则。
6. 输出路由理由后，将任务完整交给主 Skill。

## 冲突处理

| 场景 | 处理 |
|------|------|
| 同时命中研究与实现 | 最终产物需要代码时选择 `frontend-design`，否则选择 `ui-ux-pro-max` |
| 同时命中系统方法与视觉产物 | 需要系统决策方法时选择 `method-router`，需要具体视觉或图示产物时选择 `design` |
| 主 Skill 不可用 | 说明缺失项并给出职责最接近的可用 Skill，由用户确认 |
| 项目规范与 Skill 冲突 | 项目规范优先，记录被覆盖的 Skill 规则 |

## 输出格式

```text
领域：design
主 Skill：<name>
辅助 Skill：<name 或无>
路由理由：因为 <产物与阶段证据>，选择 <主 Skill> 而非 <备选>
交接范围：<由主 Skill 执行的完整任务>
```
