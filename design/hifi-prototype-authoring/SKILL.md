# 高保真原型产出

## 定位与边界

本 Skill 负责从规格、旧原型或设计稿产出**可审看、可交接的高保真源稿**。产出物是
原型/参考实现，不是生产 UI 代码；功能与数据可以 mock，但必须声明边界。

- 需要生产前端代码：交给 `frontend-design`。
- 已有权威原型，需要逐像素翻译成生产代码：交给 `hifi-prototype-implementation`。
- 需要视觉方向探索、审美决策：交给 `frontend-design`。
- 需要 UI/UX 研究、规范或可访问性建议：`ui-ux-pro-max` 只做辅助，不拥有实现。

## 共享合同

定义、保真档位、Critical/Important/Minor 严重度、独立评审资格与证据 schema、数据量
口径、失败与例外治理，以 `../references/hifi-fidelity-contract.md` 为唯一权威。本 Skill
只补充 authoring 流程与交付物，不重复定义。

## 产出流程

1. **声明范围、档位与权威基准**
   - 列出覆盖的屏/状态与明确不覆盖的部分。
   - 声明保真档位：`visual-only` / `interactive` / `data-functional`。
   - 有权威基准时写明路径、版本/哈希、对应屏；派生副本不改原目录，并写明冲突时以谁为准。
   - 纯原创没有基准时，声明"无外部权威基准"，视觉决策由本稿自身定义。

2. **四维盘点**
   - 视觉：先抽全局 token，再列局部精确值（选择器/属性/值/使用位置）。
   - 内容：标 `source-backed` / `representative` / `invented`；禁止 lorem ipsum、TODO。
   - 交互/状态：按屏列状态，不以"看起来像"代替可点击流程。
   - 功能/数据：写明 mock 边界、无后端/无持久化、哪些计数是展示值。

3. **数据量**
   - 总量、分类计数、样例行数分列；分类用树表（层级/父分类/计数/⊂/来源）。
   - 顶级分类才求和到总量；派生桶（如"其他"）标推导公式与审批人。
   - 样例行覆盖所有不同状态，或声明未覆盖；计数与可见行数不一致时标"示例 N 行"。
   - 权威基准自身错配时先确认口径，不静默改数。

4. **屏与状态矩阵**
   - 屏清单：`data-screen`、入口/出口、可达性、主要状态。
   - 状态层级：页面（初始/加载/空/错误/权限拒绝/离线/长文本）、组件（选中/禁用/展开）、
     流程（成功/失败/部分失败/重试）、视口（主视口/窄屏/宽屏）、布局（侧栏/全屏/嵌入）。
   - 每项标"适用/不适用/缺口"；"逐屏"以屏清单为准，不抽点几屏代替。

5. **锚点合同**
   - 默认约定：`data-screen`、`data-region`、`data-action`、`data-state`、
     `data-row-id`/`data-selected`、`data-prototype-only`；项目可覆盖命名，但必须写表。
   - 锚点是验证合同，不是业务 API；原型专用控件标 `data-prototype-only`，实现侧不复制。
   - 交互元素与锚点一一对应，测试可只靠锚点定位。

6. **交互接线**
   - 列交互清单：元素/锚点、所在屏、处置（`functional` / `static-disabled` /
     `static-active` / `out-of-scope`）、证据、理由。
   - 只有跳转、筛选、弹窗、状态变化、校验反馈、明确禁用原因算有效反馈；
     通用"未实现"toast 不算。
   - 看起来可点的纯展示项必须视觉禁用或标注；不允许死按钮。
   - 可访问性基线：对比度、键盘可达、可见焦点、图标按钮 `aria-label`、表单标签、
     弹层焦点陷阱/关闭后恢复、产品 UI 44px 触控目标、尊重 `prefers-reduced-motion`。
     原型专用控件可豁免 44px，但必须在缺口表记录。

7. **FIDELITY 文档**
   至少包含：
   - 头部：版本、日期、作者、标准版本、评审状态、权威基准路径/版本/哈希、变更记录。
   - 范围与档位、四维保真表、验证环境表（浏览器/版本、视口矩阵、OS、字体、服务命令、
     外部网络声明）。
   - token 表、局部精确值表、屏/状态矩阵、数据量树表与样例行说明。
   - 锚点约定、交互清单、已知缺口、失败/例外、运行与再生成命令。
   - 可访问性与第三方资源许可/网络调用说明。

8. **生成与防漂移**
   - 多屏片段/作用域样式从权威基准生成时，写生成脚本；生成物头部记录源路径与 SHA256。
   - 临时文件 + 原子替换；生成失败保留 last-known-good，并写入 review log。
   - 提供 `--check` 漂移检测；`--check` 通过只证明可复现，不等于验收通过。
   - 权威基准变更后重新生成，并复跑视觉/数据/交互门槛。

9. **独立评审**
   - reviewer 非作者、全新上下文、只读、不先看作者自评。
   - 视觉：逐屏 PASS/FAIL + 严重度 + 双侧证据。
   - 数据：逐屏文本/关键计数与权威基准对照；归一化空白、NBSP、省略号、日期/数字格式；
     内容差异与格式差异分开判定。
   - 交互：按交互清单逐项点击；FAIL 进入下一轮，不能只写"已记录"。
   - review log 落仓库内可追溯路径，保留失败轨迹到交付后至少一个迭代。

10. **验收与交接**
    - 范围缺口由具名审批人确认（影响/责任人/日期），不得包含 FAIL 条目。
    - 验收失败阻断交付；仅审批人可豁免，豁免有理由和失效日期。
    - 交接时返回：档位、范围、交付物路径、权威基准哈希、评审状态、缺口/例外、未通过项。

## 轻量档

| 档位 | 触发条件 | 交付 |
|---|---|---|
| Lite | ≤3 屏、单一流程、无权威基准派生、无跨团队交接、低风险 | 一页 FIDELITY（档位/token/状态/数据/缺口/运行）、可选锚点、一次独立评审 |
| Full | >3 屏、多流程、有权威基准/派生副本、交接给实现、多人评审或高风险 | 全部交付物 + 逐屏独立评审 + 生成/`--check` |

用户可显式升降档，但必须记录理由；Lite 也不得伪造数据或跳过 FAIL 阻断。

## 反模式

- 只做"看起来像"的页面，没有 token、状态清单和缺口说明。
- 用占位数据冒充全量，或把总数当成样例行数 1:1。
- 按钮点了没反应，或把静态项混进"已实现"。
- 手工改生成物，权威基准变了不重新生成。
- 用实施者自查代替独立评审。
- 派生副本直接改原目录，或把原型专用控件复制进生产实现。
- 把 FAIL 改写成"已知缺口"绕过验收。

## 输出建议

向用户交付时，先给一页摘要：档位、范围、可运行入口、主要缺口、评审结论；再给
FIDELITY、review log 和生成命令。不要用"已完成"替代逐屏/逐项证据。
