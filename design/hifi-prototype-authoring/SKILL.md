# 高保真源稿产出

先读 [共享验收合同](../references/hifi-fidelity-contract.md)。本 Skill 负责把已明确的需求和视觉目标做成可检查、可移交的源稿。把设计结构、关键画面、状态和验收条件一起交给实施者。项目已有规格与状态映射时引用它们。

## 1. 明确源稿范围

- 先从现有 Spec 或等价需求入口确认目标、范围和关键场景，再收集样例、已有品牌或公共组件、权威设计与目标宿主。写明版本、来源、范围和各维度档位。原创视觉方案由本稿承载，指出尚待裁定项。
- 区分源稿档位与交付体量。低风险、单流程、不超过三屏且无权威派生或跨人交接可把所需信息放在一页。跨流程、衍生发布或需要实施交接时，逐页、逐图框给出完整状态、结构、说明和证据。使用同一套判据。
- 把各入口、页面、图框、共用头部或容器的场景，以及实际数据可达性写进项目已有测试设计。早期设计探索可先记录描述性判据，开发交接前补齐精确值、允许偏差及验证方式。

## 2. 产出可对照的设计

- 为 HTML 提供运行入口、源文件和同版本截图。为设计工具提供版本、帧/节点、结构、可见状态及同节点截图。定位看不清的子区域，提供可读细节和量值。
- 先明确全局令牌和已支持的公共组件，再给实际容器层级、约束、对齐线、局部精确值与视觉例外。说明选中页签、窄窗行为、滚动归属，以及外框、插槽、嵌入页和独立页之间的关系。
- 标明素材的来源、对应区域、尺寸/比例、裁切、可用文件和必要的许可。用户内容、后端结果或其他动态图片记录渲染规则和状态。
- 用已确认的字段、顺序、文案、数据语义和代表性内容。按共享合同交代总量、分类、示例和状态。打开稿件检查空、长、密集或多状态内容的实际布局。避免用占位文本掩盖缺失的字段、操作或实际数据范围。

## 3. 接通状态和交互

- 标识入口、区域、动作、状态和行级对象。优先沿用项目稳定的选择器及可访问语义。缺少项目约定时可按需使用 `data-screen`、`data-region`、`data-action`、`data-state`、`data-row-id` 等，稳定锚点与验收编号可互查。
- 对视觉上可操作的控件列明 `functional`、`static-disabled`、`static-active` 或 `out-of-scope`。已接通的动作给出可观察反馈。静态交互明确说明状态。当前范围内仍缺设计或不能验证的控件保持 BLOCKED，其原验收项和补齐条件继续保留。用 `data-prototype-only` 或说明标记样例切换等演示工具。
- 按档位验证关键路径与失败、返回、键盘、可见焦点、表单标签和浮层焦点。支持触摸时使用项目适用的目标尺寸要求，检查对比度及减弱动效设置。列出模拟 API、持久化、权限、外部服务与真实数据缺口。

## 4. 复跑并交接

- 在项目现有文档中存放源稿入口、版本/节点、档位、状态矩阵、基准及素材、环境、运行方式与已知缺口。项目约定 `FIDELITY` 时沿用。验收清单与报告引用同一编号。
- 对从权威源生成的多屏片段或样式，复用生成流程并提供来源、可重现命令和漂移检查。生成失败保持上一可用结果。更新输入后复查受影响区域、状态、内容与交互。
- 作者先逐项自检。邀请未参与本范围产出的独立上下文按同一清单复查，检查稿件、可运行状态、关键读数和画面。已有设计或原产品作基准时获得两侧证据。原创稿件依据已确认的需求和已声明设计值核对。
- 回交可打开的原型、结构位置和同态截图，交付资料写明档位、适用范围、缺口、评审状态和未通过项。交给生产实施前检查共享合同的输入是否齐全。未能验证的范围带明确结论和依赖继续交接。
