# 高保真原型 → 像素级实现

## 定位

有明确高保真原型（或设计稿）要实现、或实现已存在要对照原型收敛时使用。
从零开始做视觉方向与设计决策属于 `frontend-design`；本 Skill 假定权威视觉
答案已在原型里，任务是忠实、可验证地翻译成项目代码。

## 核心规则

| 规则 | 内容 |
|------|------|
| H1 | 原型精确值优先——字号、间距、圆角、行高、控件最小高度逐字对齐原型数值，不做「更整齐」的归一化圆整；用户明确要求颜色也逐值对齐时从其裁定 |
| H2 | 颜色默认走项目设计令牌（或其 color-mix 派生），不硬编码原型色值；派生口径（混合比、参照令牌）写在 CSS 注释里 |
| H3 | 语义类翻译——原型类名映射为实现侧带统一前缀的语义类清单段，每段注释标注原型对应关系；同族样式只留一份宿主定义 |
| H4 | 用户 > 原型——后续用户裁定可推翻原型（退役整块、改文案）；裁定时实现与原型同步修改，同族元素一致处理 |
| H5 | 验证不过夜——每次视觉改动后走三档证据（见下），不以「文件已改」当验证 |

## 实现流程

1. **盘点令牌**：先抽原型 `:root`/全局段的字号、色板、间距、圆角、控件高度，
   与实现侧逐项对表。「整体偏紧/偏松」类系统性观感，先怀疑 token 档位整体
   偏移（如 12.5px 档被落成 12px、12px 档被落成 11px），不要逐组件修。
2. **结构翻译**：按原型 DOM 结构逐区块翻译；字段、状态位给 `data-*` 锚点，
   供组件测试与真机验证复用。
3. **文案逐字**：按钮、提示、徽章词汇逐字对齐原型；动态文案写两态。
4. **状态全覆盖**：原型每个状态色/徽章态（未处置/已完成/已排除等）都要有
   实现侧选择器、触发路径与用例。

## 三档验证证据

| 档 | 手段 | 判据 |
|----|------|------|
| ① 静态对账 | 逐属性 diff 脚本：原型选择器 ↔ 实现类映射表，比对关键字段值 | 全部相等；diff 的假阴性（复合选择器、伪类）要用 grep 复核 |
| ② 活体计算样式 | 在运行中的应用读 `getComputedStyle`，逐类核对 font-size/padding/border-radius/min-height | 在场元素全部等于原型值；无法渲染的态由组件测试覆盖 |
| ③ 并排视觉审查 | 左原型右实现、同视口截屏，拼并排合成图交视觉模型逐项比对 | 三档结论（对齐/基本对齐/明显偏差）；无高严重度；中级偏差逐条核真伪后处置 |

### 视觉审查结论甄别

- 合成图必然缩放，1–2px 级宣称是噪声级；**中级及以上才值得回 CSS 值核真伪**，
  属实的修值，不实的记录不修。
- 「整体偏 X」的系统性结论优先找 token 根因（见盘点令牌），不逐组件打补丁。
- 两侧数据内容不同不算差异——只评设计语言（结构、密度、色彩体系、文案形态）。
- 修复轮结束后重截对照图复审一轮，确认上一轮中级问题消解再收口。

## 裁定同步与退役清单

用户裁定退役某 UI 块时按清单连带清理，漏一项就是下一轮返工：

1. 实现 JSX 块；
2. 派生数据与类型声明（成为死代码即删）；
3. 组件测试断言**改向**（断言 0 块/不呈现），不删用例；
4. 高保真原型同款块与死样式（类名无 CSS 定义则免清）；
5. 行为规格制品：spec 场景改写为退役语义，注明裁定日期与撤回沿革
   （「某日裁定撤回某日的显式提示要求」这类沿革要写全，防后人翻案失据）；
6. 同族元素（他处同款提示、同款卡）一致处理。

## 工具链坑（对照链路）

- 本地截图送视觉模型：读文件再上传得到的 URL，若对象键含 Windows 路径
  反斜杠会被远端解析失败；经浏览器运行时 `emitImage` 产出干净哈希键 URL 再送。
- 并排对照图做法：临时 HTML（`img` 引本地 http 服务上的两张截图）→
  fullPage 截图 → 送视觉模型；用完删临时页。
- 热更新/整页 reload 会复位应用路由与表面（宿主 owner 链路可能断，直连 URL
  可能报错），验证前按应用正规导航路径重新进入目标表面。
- 逐属性 diff 的选择器映射表与驱动脚本放一起维护，供修复轮复跑。

## 收尾

- 提交信息写明像素对齐修复的根因（token 档位偏移/逐字值差异），不写「微调样式」。
- 对照结论与中级问题处置记录留在任务报告里，作为下一轮审查的基线。
