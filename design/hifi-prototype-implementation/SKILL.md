# 高保真实施与独立验收

先读 [共享验收合同](../references/hifi-fidelity-contract.md)。实施和验收共用该合同。只有截图时按其可证明的范围取证。只有线框或风格参考时，先收敛待设计的部分。

## 1. 开工前绑定验收清单

- 确认交付模式。实施含自测和交付给独立复核。用户仅要求审判、核对台账或验收时，按下面的独立复测执行，修改留给获授权的实施者。
- 定位原型的实际入口、版本、页面和图框，获取同版本结构与画面。HTML 读取匹配分支的模板、脚本与 CSS 并运行；Figma 读取同一节点的设计上下文与截图。若返回的是摘要或截断内容，先按图定位子节点，再取影响判定的属性、状态或素材。把截图当视觉证据。
- 从项目真实入口找到所属组件、渲染分支、宿主容器、已有 UI 规范、状态与服务契约。先画出原型和实现的页面/图框映射，包含共用头部、各页签、弹窗和嵌入内容。
- 在项目现有规格测试设计里逐页逐图框把目标翻译为测试任务。按共享合同绑定同态数据、视口、环境、操作、通过条件、容差和证据。先确认现有 Spec 的行为，再读已有台账和当前测试，沿用已有映射。未对齐、待取证、已通过的项均保留可追溯编号。

## 2. 从画面定位源码，从源码回到画面

1. **从设计画面找来源。** 对照设计与当前实际画面，标出容器位置、分栏对齐线、图标/素材、字段层级与交互区域。两端沿入口、定位、状态分支、父容器和 CSS 层叠定位实际渲染点，确定是公共主题、容器、业务内容还是数据状态引起差异。
2. **映射到项目已有实现。** 优先复用适配的宿主组件、语义令牌、图标资产、样式和行为。按约定对齐精确几何或相对关系，主题颜色按公共令牌落实，并验证对应主题。冲突写回共享清单。静态素材核对文件、使用位置、可见比例及裁切，动态素材保留真实数据路径。
3. **在正确层级修复。** 页面改动落在所属模块。跨页同源的问题定位公共容器或令牌，并确认受影响消费方。遵守项目既有授权和规划流程。同步清理受用户裁定撤回的结构、引用、关联状态、原型和相关验收映射。变化后的删除语义用已有测试验证。
4. **实现后返回运行画面。** 从产品入口进入匹配状态。检查真实内容与动态数据，执行动作并读取样式和几何。做同尺度整图和局部并排，复核差异指向的元素及处理后画面。

## 3. 在实际挂载位置自测

- 依清单完成源码/设计结构、运行读数与操作、同态视觉三类适用验证。页面源码里有数值时，也应检查实际生效的尺寸、字体、间距、边界、背景和阴影。
- 对弹窗、菜单和嵌入内容，通过真实触发点进入。检查 Portal、iframe 或宿主插槽的挂载点与令牌继承，核对内容区、头部、滚动边界、键盘和关闭回焦。窄窗检查裁切、溢出及操作可达性；有主题要求时按各主题复测。
- 对有对齐依赖的页面记录容器和关键元素的相对读数。例如左图右数核对两侧顶线、分隔线、页签位置、滚动区，以及数据证据是否能定位到左图。
- 对照屏幕执行真实入口、初始与错误等适用状态，按合同记录视口/DPR/字体、整图与局部。夹具可用于确定性的状态，记录夹具覆盖和仍需真实数据、原生宿主或外部服务的检查。回归最好断言这次实际失败的可观察属性。
- 按用户裁定或系统性修复增量复验受影响项，确认同类入口和功能行为。功能与视觉分别报告。比如「保存到…」选项可以触发，仍要检查菜单表面背景、边框、阴影及状态文字。

## 4. 独立验收与修复复审

1. 将同一份验收记录、当前设计和产品版本、可复跑的数据及入口交给未参与该范围实施的只读审判者。项目有独立复核环节时沿用。多模块可以按互不遗漏的页面区间、共享容器分工，主 Agent 核对覆盖。
2. 审判者按合同独立取证，先给逐项结果，再对读实施者证据。两者意见不同就核对环境、样例、计算样式和原稿。取证不到位记录 BLOCKED。对只有图片的设计来源，列出仅能检查画面和需要补充取证的条目。
3. 每项差距带同态截图、数值或操作、两侧定位、严重度及影响，回填原记录。定位到同一个问题的页间差异共同追因。修复后对受影响项复跑操作，并按同视口、主题、数据状态复拍。保存旧发现、修改、证据和复验结论。
4. 逐项核对通过证据、批准的例外和仍待验证的范围。接受后再更新既有基线。台账和验收报告引用最新证据及版本，保留失败轨迹。用户要求完整核对时，每页、每个图框和所需状态都有编号与结论。
