# 高保真共享验收合同

适用于 [高保真源稿产出](../hifi-prototype-authoring/SKILL.md) 和
[高保真实施与验收](../hifi-prototype-implementation/SKILL.md)。
项目规格与既有验证流程决定项目如何留档，本合同统一双方的输入、判据、证据和判定。

## 四维保真与档位

保真度描述设计在约定范围内接近目标产品的程度。按维度声明已经表达的内容及缺口。

| 维度 | 可以检查的内容 |
|---|---|
| 视觉 | 信息层级、布局、尺寸约束、对齐线、文字、间距、颜色/令牌、边框、圆角、阴影和素材 |
| 内容 | 字段、顺序、真实文案、单位、计数、状态里的具体内容及代表性数据 |
| 交互与状态 | 入口、动作及可观察结果，正常和边界状态、响应式变化、键盘、焦点与恢复 |
| 功能与数据 | 数据源与身份、业务规则、持久化、外部调用和结果，按项目规格和证据条件验证 |

| 档位 | 源稿至少表达 | 典型用途 |
|---|---|---|
| `visual-only` | 视觉、内容，声明交互与功能缺口 | 静态设计评审 |
| `interactive` | 视觉、内容、交互与状态，声明功能与数据缺口 | 流程评审、实施交接 |
| `data-functional` | 四维及相应流程证据，注明真实数据/逻辑边界 | 复杂流程演练、预生产验证 |

保真档位描述源稿。生产行为仍须遵循项目规格。纯截图可以支持已标定画面范围的比对，未知精确值、未呈现的状态与动作记为缺口。升档或改变范围后更新声明并复验受影响项。

## 确立基准

- 项目使用 Spec 时，先在现有变更确认用户目标、行为范围、入口和关键状态。源稿表达视觉方案，规格测试设计把源稿变成可执行判据。范围已经有对应变更时沿用它，缺少或冲突的要求按项目流程补齐后再实施。
- 记录适用的用户裁定、项目行为规格及公共 UI 规范、权威设计入口和版本、屏或节点、样例来源、实现或源稿的检查版本。源稿有多套时逐项写明采用的版本和适用范围。
- 用户已确认的范围及覆盖项同步到相应规格、源稿和测试记录。业务行为查项目规格，视觉目标查已采用的稿件，公共规范查项目组件与令牌。遇到要求冲突，定位受到影响的具体项，记录两侧证据并解决冲突再做依赖工作。
- 现有产品只有被指定为参考时才作为相应项目的预期。发现落后于裁定的存档、样式分支或截图时，保留其来源，重绑受影响项并重新取证。
- HTML 源稿使用实际生效的模板、脚本和 CSS 与同入口实拍。Figma 或其他编辑器使用同一版本、同一节点的设计结构、属性和截图。先解决不同入口、版本、状态或裁切造成的冲突。

## 同一份验收清单

**开工前把高保真定义转成规格测试设计里的检查项。** 实施者与验收者使用同一份基准、编号、预期和偏差。只有独立验收交付时，也先核对这些前提。优先复用项目的规格测试设计、案例映射和验证记录。项目没有正式规格流程时，可以在原有任务或交付记录里保留同等信息。

1. 按实际入口枚举每个页面、每个图框与共用容器。为该范围登记初始、加载、空、失败、权限、极长内容、选中/禁用/悬停/焦点、完成/取消/重开等适用状态。窄/宽窗、主题、嵌入/独立入口及支持的宿主布局在影响预期时各列覆盖。标明不适用原因和已知缺口，避免机械组合。共用规则可复用同一个判据，同时明确需要验证的消费入口。
2. 为每项记录 **编号、维度、定位、基准版本和来源、入口与环境、数据和前置、操作、预期结果、允许偏差、取证方式**，映射到可执行或可复现的测试任务。保真档位、场景范围、预期值已知时写成观测条件。记录状态与证据走项目已有入口。
3. 按要求定义判据。必须精确的内容、尺寸和边界写具体值，复用公共规则时写对应令牌、组件或相对关系。确需允许偏差时写清适用环境、度量和理由。合成图缩放、设备像素与 CSS 像素的差异需校正后复测。未约定的差异以原始证据核实，发现后不得临时放宽判据。
4. 绑定预期后再实施、造数或生成快照。若设计或规范变更，记录裁定与影响面，同步清单、测试和需要更新的原型后复测。两侧无法到达同一状态或版本时，继续独立可验证项，并保留受影响项的缺证状态。

## 取证与独立复测

| 证据 | 如何取得 | 可支持的结论 |
|---|---|---|
| 源码/设计结构 | 从同一图框的设计节点或原型源码，映射到项目入口、实际组件分支、状态条件、样式层叠、令牌和素材；从成图反向定位实际生效处 | 结构、属性来源和实现路径 |
| 运行读数与操作 | 在声明的宿主和真实入口中激发场景。抽取关键几何或计算样式，执行动作并记录可观察结果 | 指定状态的实际尺寸、样式、交互或功能 |
| 同态视觉 | 比对同一入口与数据状态，标明宿主/浏览器、CSS 视口、图片像素、DPR、缩放、主题与字体。等字体、素材和画面稳定后，保留原始图，校准比例、裁剪、设备外框。先同尺度并排看整体，再看有差异的局部 | 指定环境、区域和状态的视觉比对结论 |

有源码和运行画面时完成 **原型源码/设计结构 ↔ 项目源码** 和 **原型画面 ↔ 实际产品画面** 两组比对。读数与截图冲突时先定位真实入口、状态、渲染和截图版本。自动快照可以辅助检测漂移，需确认对应同环境、同范围及已接受的预期。屏蔽动态内容前说明范围，保留被验收的区域和关键状态。

- 实施者按清单自测。未参与该范围产出或实施的独立上下文只读复测，读取同一验收清单，用同样的条件先独立判定，再核对实施证据。缺少所需独立复测时标记对应验证 BLOCKED，记录影响。
- 每个结论回填原编号。保留目标版本、两侧可复查证据、实测差异、严重度、取证范围、检查人及时间。范围较大时按页面或共享容器委派只读检查，汇总时核对每项均有结论。
- 发现差异后回到对应所有者修复。复拍同一状态和视口，回归相邻分支和受影响消费者，关联旧发现、修复与新证据。两轮无改善时重新检查根因。复审接受后更新项目已有基准。

## 判定与收口

| 状态 | 判据 |
|---|---|
| PASS | 该项所需证据齐全且符合通过条件 |
| FAIL | 可比证据证明不符合条件，记录严重度和修复后复测 |
| BLOCKED | 版本、入口、证据或环境前置缺失，当前无法得出通过结论 |
| 不适用 | 该项从项目约定范围排除，记录依据 |
| 已批准例外 | 引用具名裁定、原因、适用范围与失效条件，保留原差异及复验约定 |

| 严重度 | 判定与处置 |
|---|---|
| Critical | 破坏布局或关键操作、功能误导、数据或结论错误、安全/可访问性关键路径失效。阻断，修复并复审 |
| Important | 明显观感、流程或数据差异，影响理解、使用或交接。修复并复审，或由有权人批准例外 |
| Minor | 局部细节差异且不影响理解与操作。记录并按项目验收约定处置，保留真实结论 |

分别报告视觉、内容、交互和功能证据。单元/夹具、浏览器、原生宿主、真实模型或外部服务各证明自己的范围。未执行、不可达、夹具替代与尚待验收的情况如实记录。整页或整轮通过前核对全部要求的条目、证据和例外，保留未通过项及修复轨迹。范围缺口写明影响和处理决定。已声明范围内缺证用 BLOCKED，已有反证用 FAIL，范围变更引用裁定。生成失败保留上一个可用版本与失败原因。

## 数据口径

- 分列总量、分类计数和样例行数。记录来源、统计截止日期、计数单位、去重与排除规则。分类提供层级、父项、计数、包含关系和来源，只有互斥的顶级分类可求和。
- 派生桶注明公式和批准依据。样例覆盖要求中的不同状态或状态组合，未覆盖的按范围缺口记录。展示总量超过样例时标明实际样例行数。
- 内容标 `source-backed`（源值一致）、`representative`（注明选择方法和覆盖范围）、`invented`（仅限可使用的虚构内容）。读数冲突时先对齐口径。
- 只有验收约定允许时才归一化空白、省略或日期/数字格式。分别核对内容与表现，字段、单位、计数、状态和用户可见格式均按对应判据检查。
