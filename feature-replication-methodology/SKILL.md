# 跨仓库功能复刻方法论

## 复刻目标与项目流程

先根据用户要求确定本次模式，不把源码现状自动当成产品目标：

- **忠实复刻**：用户要求行为或像素一致时，以源端可观察行为为基准；缺陷和必要偏离逐项说明。
- **结果对齐并优化**：用户明确允许按新功能优化时，保留已确认的用户结果，允许复用目标仓已有入口、合并重复页面、简化交互，并修正源端缺陷。为每项优化写清原行为、目标行为、理由、影响和验收；不能把未实现换名为优化。

历史兼容不是默认目标。只有已发布契约、实际外部消费者、须保留的用户数据或用户明确要求构成依据时，才保留旧接口、迁移、兼容分支及双路径。新功能可以直接收敛成单一正确路径；这不授权删除用户数据或其他任务的改动。

本 skill 提供当前阶段的调查与验证方法，服从项目的规格、授权和验收流程。优先把信息写入已有权威制品；不强制另建台账、图文件、阶段、审批或每任务组实机门禁。项目禁止使用提交号或指纹作为规划身份时，沿用其外部来源记录规则；不能因缺少本 skill 模板而暂停。监控若有独立授权也遵守原通知策略，不因 R23 为制造产出而改动无关代码。

## 前置条件

- 源仓库或明确的源码快照可访问；记录项目允许的来源位置与版本信息。无版本控制的快照不伪造版本锚点，也不声称已对齐最新。
- 目标仓库可读取；进入实现验证时至少一类构建与测试命令可用。只读审计允许记录环境限制，不把无法运行算通过。
- 已确定要复刻的功能名称与源码入口
- 已确认源码许可与第三方归属允许搬运

## 项目绑定（调用方提供）

本 skill 只规定方法与判据，不内置任何项目路径、名称或命令。先从当前上下文和项目权威制品确认以下绑定信息；项目无现成承载且需要持久化时，可参考 `references/project-binding.md`，不强制创建副本：

| 绑定项 | 说明 |
|--------|------|
| 源仓库路径 + 版本锚点 | 本次复刻的基线 |
| 目标仓库路径 + 构建/测试命令 | 验证入口 |
| 运行实例启动方式与隔离参数 | 并行实例的端口、调试参数、状态目录 |
| 调试与取证通道 | 日志、进程级调试端口、状态库、UI 自动化 |
| UI 断言通道 | 程序化输入与截图方式 |
| 项目专属规则文件 | 该项目已踩过的坑与既有约定 |

绑定项先从用户上下文、仓库配置和现有制品读取并验证；仅对无法发现且影响操作的缺项询问，不猜测路径或命令。

## 场景路由

| 用户意图 | 对应章节 |
|---------|---------|
| 复刻一个新功能（从零开始） | 支柱 1 装配链先通 |
| 功能写了但不生效 / 调用方看不到 | 支柱 2 声明面多层一致 |
| UI 元素不出现 / 界面与源不一致 | 支柱 3 证据驱动验证 |
| 两仓跑同一用例结果不一致 / 判定回归还是预期变更 | 支柱 3 黄金基线 + 一致性台账 |
| 移植前准备 | 移植前冻结 |
| 移植完成收尾 | 收尾审计 + 一致性台账 |
| 测试用例移植 | 支柱 3 黄金基线 + 一致性台账 |

## 支柱 1：装配链先通

> 复刻不是翻译代码，是接通链路。先画装配链路图，确认每条链在目标仓库走通，再写代码。

### 操作步骤

1. **画装配链路图**：回答四问
   - 功能入口被激活时，上下文属于哪棵树/哪个容器？
   - 能力（工具、服务、组件）注册进哪个实例？
   - 可见面（调用方可见清单、页面渲染）从哪聚合？
   - 同一功能有几个实例并存？
2. **找同款先例**：读取源仓与目标仓已跑通的同构路径，理解它解决的结果；忠实模式保持语义，优化模式选择符合目标仓拥有者边界的最小实现。
3. **识别多树/多实例陷阱**：多容器共存是常态，按实例逐一确认归属
4. **最小纵向切片**：选一条行为，打通「注册 → 可见 → 执行 → 呈现」全链再铺量

### 完成标准

- [ ] 装配链路图已画（各树/容器 + 可见面聚合点）
- [ ] 行为清单已列（每条可观测行为 + 验收方式）
- [ ] 同款先例已定位（路径 + 行号）
- [ ] 实例数量与隔离方式已确认
- [ ] 首个纵向切片端到端通过

## 支柱 2：声明面多层一致

同一能力通常需要在多个声明点同时登记，缺任何一层都会出现不同症状，且多数不报错。

### 通用四层（按目标仓库实际层名映射）

| 层 | 典型位置 | 作用 | 缺失症状 |
|---|---------|------|---------|
| 1 | 组合/装配声明 | 产物是否包含该能力 | 产物中不存在 |
| 2 | 可见清单（调用方可见的 schema/规格） | 调用方能否看见 | 清单不含，无报错 |
| 3 | 执行注册 | 能否真正调用 | 可见但调用时报未接线 |
| 4 | 会话/请求规格 | 本次会话是否携带 | 主流程里不可用 |

### 操作步骤

1. 逐层检查四层声明是否都有 → 补缺
2. 校验闭包语义：声明面随打包裁剪整体退场，无悬挂引用
3. 载荷按契约映射，不原样过边界

### 接口变更：先判断是否需要兼容

仅对有实际兼容责任的接口使用下面的顺序；新功能无外部消费者时可一次更新定义、执行与全部消费点，不为形式上的安全增加旧分支。

- **expand**：新增兼容形态（加可选字段、加新入口），旧形态保留
- **migrate**：逐个消费方切换到新形态
- **contract**：确认旧形态无人使用后再删除

判据：加可选字段是安全变更；删除消费方依赖的字段、修改字段类型是破坏性变更。

### 契约断言（轻量，不引入框架）

- **只断言消费方实际用到的字段**：按 schema/类型匹配断言，不追提供方全量 schema——过度规格化会让无关变更误报
- **断言三态**：新增可选字段放行；删除消费方依赖字段、字段类型变更必须失败
- **事故回流**：任何在集成环境暴露的接口问题，都要补成一条契约断言，否则同类问题不会被门禁拦截
- **契约覆盖 = 消费方用例覆盖**：没被用例走过的交互，等于没有契约保护

### 错误处理（症状 → 检查点）

| 症状 | 优先检查 |
|------|---------|
| 可见但调用报未接线 | 层 3 执行注册 |
| 清单不含但无报错 | 层 2 可见清单 |
| 执行成功但下游拿不到上下文 | 层 4 会话/请求规格绑定 |
| 只读能力未接线 | 读取端口的装配 |

## 支柱 3：证据驱动验证

### 四档（由低到高，重要结论用高档）

| 档 | 手段 | 判据 |
|----|------|------|
| 0 | **黄金基线**：移植前从源仓跑出实际输出，归一化后冻结 | 移植后零差异，或有差异逐条判定 |
| ① | 静态对账：类型检查 + 产物清单对账 + 测试全绿 | 全部通过 |
| ② | 活体检查：运行时读取实际状态（计算样式、schema、事件序列） | 实测 = 预期 |
| ③ | 实景操作：真实输入后截图/状态存档 | 元素在场且形态正确 |

### 黄金基线纪律

- 非确定性值（时间戳、随机 ID、迭代顺序、浮点格式）在边界归一化，否则每次都是噪音
- 有差异必须逐条判定：预期变更（更新基线）还是回归（修代码）
- **禁止无脑更新基线**——橡皮图章式的快照更新等于零保护
- 冻结时已知的缺陷要标注（注释或工单），后续作为独立变更修复
- 只冻结本次改动涉及的分支，覆盖跟随变更，不求全量

### 双仓对照评估（同一输入跑两边）

同一输入（snippet、脚本或请求）在源仓与目标仓各自的装配链上直跑（用同构临时文件树），四维度采证：

| 维度 | 采什么 |
|------|--------|
| 结算/输出形态 | 最终产物与返回结构 |
| 日志捕获 | 两侧日志级别与关键字段 |
| 事件类型序列 | 事件种类与顺序 |
| 时长画像 | 各阶段耗时（单次采样不作性能结论） |

逐维度给双侧证据，无法判定的维度明确写原因；判断「两边都没有」时按 R15 做双侧逐行 diff。

### 完成状态与真实入口

恢复或收尾时先核对当前源码、实际入口和证据对应的版本/时间。任务勾选、提交标题、旧报告或追加日志都只是线索，不能独立证明当前完成。旧阻塞被后续实现推进后，不照搬旧失败；新实现也不能继承修改前的实机通过结论。

对每条关键用户路径同时追踪“界面输入 → 请求载荷 → 宿主处理 → 状态归属 → 结果呈现”。新增可选字段或端口方法不等于调用方已使用；例如后端支持会话标识，但启动按钮未传且宿主未创建关联会话，仍是断链。除成功路径外，核对本次实际涉及的拒绝、失败和取消后的会话/文件/运行残留，不为了覆盖所有假想风险扩张设计。

并行观察不等于依赖拓扑。时间重叠可以支撑“实际并发”，不能冒充静态依赖图、确定的分叉汇合或尚未执行的计划。展示名称与数据证据相符，数据缺失给出准确状态。

### 多入口与状态生命周期验收

同一能力往往同时出现在聊天卡、启动预览、运行详情和宿主文件查看器。先列出实际生产消费者，再逐个验证默认态、进行中、等待、完成和失败中本次适用的状态；修复共享组件后，也要确认每个入口真的消费它。单独挂载组件通过不能证明正式注册和卸载重挂路径通过。

返回原页面时，不只检查版本号：阶段/分组展开、图形层级与缩放、选中节点、产物展开都会改变布局高度。用真实“选择历史版本 → 打开宿主预览 → 返回”验证，并比较内容锚点；补正式入口卸载/重挂回归。临时浏览状态按工作区与运行隔离，由既有页面生命周期拥有；新显式定位优先，不另建导航历史，也不把浏览选择写入业务日志。

静态计划与执行事实分别核对。图中有节点不证明运行到达，整体完成也不意味着所有条件分支执行；已提供实现的人工节点、循环实例、恢复重放和未走分支应有各自的事件证据。修正缺失的执行事件，不通过把所有节点涂绿掩盖投影错误；旧日志没有事件时，不伪造历史完成事实。

同一组件的不同消费者可能绑定不同回调。逐个核对按钮文案、实际目的地、可见目标与输入焦点；“查看待答问题”应到对应答复入口，不能因聊天卡正确就推定详情也正确。用实际消费者测试等待与普通状态，防止修复待答导航时破坏正常会话入口。外部入口跳转与页面内部定位分别验证：进入后不再点击输入框，直接输入并回读，才能证明焦点已交接。

插件已注册展示槽不代表宿主在所有状态都渲染它。检查宿主的实际条件与优先级，例如忙态指示器是否覆盖插件标记；若依赖另一个公共入口补足发现性，实测它的触发条件和可达路径。悬浮卡、弹窗等宿主表面须在真实背景上核对文字对比度、换行和点击范围，不能用独立组件的浅色截图代替。检查实际颜色继承链：宿主标题单独着色不代表插槽可继承；没有可用的表面前景时，使用既有语义前景与背景成对配色，再复验实际表面。

节点结算、工具结果返回、原生轮次结束与资源释放是不同事实。同一参与者连续调用、停止后恢复须分别验证；成功结果已写入但原生轮次未结束，仍可能堵住后续执行。重复或迟到提交必须明确结束，不能向已终态节点建立无人兑现的等待。按调用标识和事件顺序核对原始记录，不能把界面聚合的“工具运行中”误认成首次调用尚未返回。

父模型的总结和脚本中的计划不能替代运行事件与当前待办。插件问题与宿主另行创建的问题要辨明拥有者，前者完成不证明后者已清理；未经合同支持，不以取消整个父会话冒充问题同步。记录已通过的边界和仍开放的交互。

### 文件与逐帧证据的最低有效性

- **样本可辨认**：视觉样本要有独立可核对的标题、编号、颜色或数值；空文件、单像素图及无正文文档只能证明入口可达。按项目测试数据规则复用或局部生成样本，不能用生成器自己的输出宣称预期正确。
- **分层验文件**：页面内展示、宿主预览、外部应用打开、保存对话框与实际下载分别记录。对话框出现不等于落盘；下载后比较所选版本的字节、大小或摘要。单页栅格PDF不证明文本提取、多页或无障碍。
- **逐帧看内容**：采集后实际打开图片，核对窗口、运行、版本和关键正文，不凭文件名、截图存在或模型回复判定。持久自动化会话可能误用旧截图；保存本次观察返回的图像，失效证据保留但明确作废用途，用新帧补证。
- **设计与功能分别判定**：按钮可点击、文字未溢出不等于设计合格。按实际容器宽度检查信息层级、字号、内容可辨识、空白、首屏待办和返回位置；窄侧栏不能用宽窗口截图替代。缩略图须区分“识别内容”与“阅读正文”的目标。
- **独立复核可被纠正**：复核者须实际看指定图片或读取文件；意见冲突时回到同一组内容锚点和原始数据，不按角色权威选结论。同源环境的复核如实说明局限。

### 证据通道交叉

单一通道会漏，重要结论至少两路交叉：

| 通道 | 能看到 | 盲区 |
|------|--------|------|
| 应用诊断日志 | 装配/失败事件 | 错误字段可能是脱敏投影 |
| 进程级调试通道 | 完整错误对象、真实 DOM | 需直连运行进程 |
| 状态库 | 运行状态、事件序列 | 需一致性快照（WAL 等） |
| DOM/结构查询 | 可见实例的节点 | 多实例时可能命中隐藏实例 |
| 框架内部探针 | 组件内部状态 | 并发渲染可能丢弃调用 |

## 移植前冻结（第 0 步）

1. **版本锚点与许可**：记录源仓 commit/tag；确认许可与归属允许搬运
2. **回归陷阱清单**：列出目标仓**已改进、可能被源版本冲掉**的行为，移植后逐条复验
3. **行为清单**：每条可观测行为 + 验收方式，与链路图一起作为规格
4. **黄金基线**：按支柱 3 的纪律从源仓采集并冻结

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|---------|
| R1 | 组合产物中的保留路径只允许类型导入，禁止值导入 | 产物在隔离环境解析外部依赖时报类型错误 |
| R2 | 声明面多层一致（组合声明 / 可见清单 / 执行注册 / 会话规格） | 调用方不可见，或可见但执行报未接线 |
| R3 | 可见面可能经中间合并层聚合，不直连注册表——外部能力必须显式声明到该层 | 注册了但调用方永远看不见 |
| R4 | 开发服务器/打包器的预打包缓存——源码改动后必须重启或清缓存 | 在旧缓存上调代码，以为修了但没生效 |
| R5 | 多实例共存是常态——取证必须过滤不可见实例 | 撞隐藏实例，误判为状态衰减 |
| R6 | 宿主诊断字段可能是脱敏投影 | 只看日志永远拿不到完整错误对象 |
| R7 | 组件身份必须稳定（禁内联包装导致重挂） | 框架判别为新组件 → 卸载重挂 → 局部状态丢失 |
| R8 | SSR/静态渲染下外部 store 订阅走服务端快照（恒缺席） | 高频重渲染场景不可用，改用快照读取 |
| R9 | 冲突残留（stash pop 等）必须即时清理 | 配置/JSON 损坏，启动失败 |
| R10 | 载荷不原样过边界（按 wire 契约映射） | 客户端按存储形态消费 → 类型错误 → 整块降级 |
| R11 | **落盘即接线**：组件/模块落盘前先建消费者（stub 也行）；宿主端口声明属于声明面，新增需同步「端口声明 + 注册 + 消费」三处 | 组件完整、样式齐备、零消费点，功能永远不出现 |
| R12 | 流水线执行器的 cwd 是主会话工作区，不是任务工作树——测试与写入路径必须绝对化并在人设写明防越界 | 测试跑了别的仓库；执行者越界改主仓库 |
| R13 | 程序化输入（合成事件）可能被忽略——注入后必须轮询「用户可见效果出现」确认成功，失败重注入设上限；真实输入设备是可靠替代。**CDP 真实鼠标事件（Input.dispatchMouseEvent）也要校验坐标在视口内**（getBoundingClientRect 的 y 超过 window.innerHeight 即落空且无报错——dev 重启后窗口尺寸常变）；坐标超界/点击无效时 **Enter 键（dispatchKeyEvent）兜底是可靠通道**（composer 聚焦+Enter 发送实锤） | 点击落空静默无报错，误判「功能回归」（实锤：窗口高 ~750 而按钮 y=854，连续 4 次发送失败被误判成插卡回归） |
| R14 | 并行实例隔离三件套（端口 + 调试参数 + 状态目录）——起实例前查端口占用；操作前核对实例归属；开发服务器自动换端口会导致实例加载错前端 | 数据写进别人的实例目录 |
| R15 | 「两边都没有」的结论必须双侧逐行 diff 背书——grep 未命中 ≠ 不存在（实现可能换名） | 误判「需立项」实为「已对齐」 |
| R16 | 迁移完成必跑两个收尾审计：导出面 × 消费点交叉核对；样式/资源孤儿比对 | 「已定义未消费」静默搁浅 |
| R17 | 对齐检查的参照基线可能是**静态快照**（无 .git，无法拉新）——检查前先核快照日期与更新通道；无法更新时报告必须声明基线日期，防「已对齐最新」误判 | 把旧快照当最新源码，审计结论过期 |
| R18 | 移植源仓库 CSS 组合器前先验目标 DOM 真实结构——源规则可能是**实际命不中的死选择器**（实锤：后代组合器选灯，而灯实为按钮兄弟节点），逐字照抄=移植死代码 | 规则注册了但永不命中，假接线 |
| R19 | 定性「功能回归」前必须先做**受控实验**终判（实锤：Stop 后不 Resume、journal 查终态——cancelled 即 Stop 有效），并复做一次「发送→观测」闭环（同脚本内发送+采样，别分两个脚本）——发送通道静默失败/时间窗错配/多 run 卡遮蔽都会伪装成回归 | 误报回归，浪费整轮修复定向（第 3 轮实锤：把「复跑型回合多卡遮蔽+发送失败」误判为插卡回归） |
| R20 | **宿主级单例服务的「会话归属比对」必须谓词化**——源仓库 per-session app 里「run 属本会话」是架构自然产物，目标仓宿主级单例的服务级常量（如 local-host:<id>）与真实发起会话 id/匿名 NULL **永不相等**，等值比对=静默挡掉全部数据（三次实锤：进度汇闸门/产物读口授权/内省读面）；修法=sink 的 `ownsSession` 谓词模式，宿主装配传「判活会话」，匿名（缺席）按已批准的身份合同处理，不能为接通数据自动放行 | 数据通道整条静默失效，实机才发现（产物读口 41 条历史 run 全读不到） |
| R21 | **新增运行时 command/query 的登记五件套**：①wire 常量与载荷校验 ②run-channel/通道注册 ③composition commandIds/queryIds 声明 ④editions×5 期望 JSON ⑤消费端——漏 ③④ 宿主直接起不来（HOST_PROCESS_START_FAILED，声明面 vs 运行时注册精确闭包对账），漏 ⑤ 假接线 | 三次实锤（saved-delete/saved-move/artifact-read/saved-save），每次都在实机启动或闭包测试才暴露 |
| R22 | **实机采证的输入注入优先新开会话**——发送通道免疫期的重试会往共享会话堆积无消费消息（36 条 user 零回复），污染对话流且让「run 卡在场性」等判定失真；采证前核对实例归属（R14）+ 会话新鲜度 | 抽查疑点误判（卡全空实为注入堆积会话，排查一轮） |
| R23 | **值守与例行检查遵守授权范围**：有证据支持的问题才推进必要修复或记录；无变化、无新问题时保留已有状态，并沿用户通知策略保持安静。不为凑每轮产出新增测试、文档、代码或审批 | 无依据的变更扩大范围，制造噪声并增加回归风险 |
| R23b | **样式类删除后必须①大括号配平扫描②真实启动 dev 验证**——vitest 不解析 CSS，gate 全绿拦不住语法损坏；「删段后 dev 起不来的 CssSyntaxError」曾被两轮误判为「dev server 瞬态」（实锤：行号删除残留相邻规则的闭合大括号） | 提交带病 CSS，dev 不可启动且误判为环境瞬态 |

## 一致性台账

每个能力一行，状态只有四种：未开始 / 已移植待验 / 已验证 / 故意偏离。**故意偏离必须写理由**，
否则后续审计会把「有意不搬」误判为缺口。优化模式的差异另注明替代结果及其验证状态；只有理由而没有完成替代结果，不能算交付。模板见 `references/parity-ledger.md`。

维护一份当前状态摘要；历史记录可保留，但应明确哪些结论已被替代。记录测试对应的实际源码、安装版本和覆盖范围；补丁后的定向测试不能改称新版本全量通过。归档前对照逐场景证据，不把未验证项改名为故意偏离，也不以提交代替验收。分别报告实现、自动测试、真实入口/安装版验收和归档状态，避免过期缺口与新证据相互覆盖。

## 收尾审计（迁移完成后的强制动作）

1. **导出面 × 消费点交叉核对**：列出每个组件/模块的导出，逐个全仓查找消费点（排除定义自身与测试）——零消费即缺口候选，再判定：内部子件（非缺口）/ 真缺口（给出应消费位置）/ 死代码（删除）
2. **样式/资源孤儿比对**：样式前缀 × 引用位置；孤儿意味着「写好了但没接全」
3. **规范源对照**：每个真缺口查源仓库同名实现在哪被消费——消费位置就是移植落点
4. **台账对账**：逐条收口一致性台账——「已移植待验」不得计入完成，「故意偏离」须有理由
5. **可回滚确认**：采用已有功能开关或版本控制回退边界；仅在存在实际兼容责任时保留旧路径，不为新功能另造开关、双路径或迁移。
6. **回执落盘**：审计结论、证据位置、残余风险、回滚方式与开关名写成可追溯记录，不只留在会话里
