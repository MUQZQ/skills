# Magpie 模型路由

目标是用较低的总成本拿到可验收的结果。一起考虑现金支出、套餐额度、等待时间和返工。
Magpie 在网关处理整轮选模与回退，客户端原生 Agent 负责拆任务、启动子 Agent 和验收。CCS 可以提供工作方法，运行时不要求安装 CCS。

## 先确认现场

1. 确认目标是本机还是远程 Magpie、哪个客户端和哪个会话。通过本机已安装的 CLI 或界面读取组成员、顺序、会话保持、规则和客户端默认模型。
2. 用 `magpie groups`、`magpie group <id>`、`magpie group rule <id>`、`magpie models <agent>` 和 `magpie <agent> model` 区分目录可见、实际组成员、客户端默认和当前会话所选模型。选了某个独立模型的会话不会自动使用组的回退。
3. 通过用量、额度和路由记录确认账号可用性与实际命中的模型。按免费试用、已付套餐、按量付费、未知四类归账。试用可能过期或返回 429；历史成功、目录带有免费标记、零估价都不能证明当前可用或无费用。只输出判断所需的模型、额度和状态，不打印凭据或会话内容。

## 分组和用法

当用户沿用经济优先方案时，复用现有两组：

| 入口 | 顺序 | 用途 |
| --- | --- | --- |
| `main` | 日常主力套餐 → 另一套餐 → 明确允许的按量模型 | 连贯开发、排查、改代码和最终验收 |
| `cheap` | 确认的免费或试用模型 → 已购套餐里的轻模型 → `group/main` | 独立的批量日志、巡检、证据收集或有明确验收的轻任务 |

- 设为按顺序回退。两组可以按轮保持，新一轮再从策略决定首选。把 `main` 作为 `cheap` 最后一项，避免重复维护付费模型。禁止反向嵌套造成回路。
- `cheap` 直属成员只放免费或已购套餐模型。包含 `main` 意味着所有前序模型都不可用时，仍可能按量计费。若用户要求**零额外付费**，这类任务使用去掉所有付费路径的组，连嵌套组和供应商级回退一起核对。
- 参考映射：`main` 为 GPT-6.2 Sol → GLM-5.3 → DeepSeek V4.1 Flash；`cheap` 为 GLM-5.3-Flash-Trial → GLM-5.3-Trial → GPT-6 Luna → `group/main`。这些是示例，不是可用性或价格承诺。Luna 与 Sol 可能占用同一订阅额度，不算独立额度池。沿用用户“DeepSeek 只用 Flash”的约定时，禁止把 Pro 当替补。
- 小而紧密的任务由主模型直接完成。只有当子任务可独立交付、好验收且节省的时间超过交接成本时才委派。给轻模型提供必要输入、限定读写范围和验收证据。主 Agent 负责关键判断、整合与最终验收。正式独立检视选合适的强模型（如 Sol `high`），疑难或高风险问题再按证据升级。
- 要在同一次任务中分工，用客户端的原生子 Agent 或明确指定角色模型。避免全局子代理覆盖把轻量执行和正式检视统一降档。Magpie 能路由收到的请求，不会生成子任务。

## 规则何时使用

- 仅需费用顺序和回退时，规则与意图判断模型都可以留空。
- 如果多个客户端需要统一入口，且用户愿意显式标记整轮任务，再考虑单独入口组，通过 `轻任务：` 等前缀优先选 `cheap`，无需分类调用。未命中走 `main`。确认嵌套和规则的回退不会重复请求，保留两个基础组的原用途。
- 只有用户需要按自然语言自动选整轮模型，才考虑少量互斥意图，用便宜而快速的分类模型。意图分类增加一次可能计费的调用；命中调整候选顺序，不等于约束可用模型范围，也不应把“查 CI 并修复”整轮当成轻任务。

## 更新和回读

仅分析时交付现状与建议；用户要求更新时，按授权修改指定组或客户端绑定。先检查 CLI 帮助和实际目录，记录原成员、模式与规则，再用 `magpie group set <id> models=<逗号分隔的成员> routing=order stays=turn` 或界面的对应控件写入。保留未涉及的账号、客户端绑定和规则；如发现配置漂移，说明具体差异，按本次确认的策略修正。

保存后回读两组和相关规则，检查付费模型只出现在授权路径、嵌套无环、目标客户端会话选对入口。留意长上下文或能力不匹配也可能跳过首选。用户要求实测时用最小请求，从 Routing 或 Usage 记录核对请求组、实际模型、状态、耗时、费用类别；未触发真实回退时标明回退仅经配置核对，不故意耗尽额度。若再次发生漂移，先核对本机和使用中的同步配置来源，再处理反复覆盖。
