# 七类基准的断言提取法

编册前按本文为每个基准物选类、按类提取原子断言。每类给出：真相形态、提取配方、证据手段、适用要素、降级注意事项。

## 0. 通用规则

- 一条断言只判一件事；断言动词必须可观察（存在/等于/返回/显示/拒绝/触发），禁"正常/合理/友好"。
- 每条断言标注层级（T1/T2/T3）与证据要求（真数据/录制/构造 + 采集方式）。
- 规格类基准必须建立**双向索引**：每条 requirement ↔ 至少一条断言（或显式 NA），漏提即覆盖度门禁失败。
- P0/T1 语义来自阶段 0 映射表，本文的级别示例仅供参考。

## 1. UI 稿（信息架构/高保真图）

- 真相形态：设计图 PNG/Figma/原型 HTML/草图。
- 提取配方：按区域分解——导航结构 → 布局分区 → 每区组件 → 数据字段 → 按钮与命令 → 状态覆盖（首次进入/空/加载/错误/离线/只读…）。每个区域一条结构断言 + 五项视觉检查维度。
- 证据手段：自动化截图（固定 viewport/DPR）与基准并排对照；交互类用真实操作序列；视觉回归测试（若存在）可作录制档证据。
- 适用要素：五项视觉检查、状态尺寸记录、交互运行时检查全启用。
- 注意：设计稿是演示数据时，实现必须用对等 fixture 数据对照（保证可复现）；真实数据仅用于链路类检查并记录 market session。

## 2. 架构图（结构/模块/进程边界）

- 真相形态：分层图、模块图、部署图。
- 提取配方：每个方框/边界/连线各成断言——模块存在性（目录/组件/路由）、依赖方向（谁可以 import 谁）、进程边界（谁和谁不同进程、崩溃隔离语义）、禁止项（图上标 ✗ 的越权能力）。
- 证据手段：代码结构检查（文件/依赖 grep）、配置检查（manifest/capabilities/CSP）、运行时探针（进程列表/端口）、专项测试。
- 注意：架构图的"结构性偏差"按映射表可判 P1 甚至 P0（如安全边界突破）。

## 3. 契约图（协议/接口/数据流约定）

- 真相形态：时序图、协议字段表、端点约定。
- 提取配方：每个时序步一条断言（顺序+前提+结果）；每个字段一条断言（名/类型/语义/版本）；每个失败分支一条断言（超时/不匹配/拒绝时行为）。fail-closed 标注必须成断言。
- 证据手段：契约测试（pytest/vitest）、协议生成物漂移检查、真实端点探针、fault harness。
- 注意：协议类断言的证据通常可以完全引用现有测试——先映射再人工。

## 4. 流程图（业务链路/状态机）

- 真相形态：业务流程图、状态机图、泳道图。
- 提取配方：每个状态一条断言（可达+出口完整）；每个转移一条断言（触发条件+守卫+副作用）；每个异常分支一条断言（人工处置/回退/降级）。
- 证据手段：领域层单元测试、e2e 场景、审计/日志证据。
- 注意：状态机类断言必须覆盖"未运行/首次进入"态——真实评审教训：只查运行完成态会漏掉首入空态缺陷。

## 5. 规格场景（OpenSpec/需求文档 WHEN-THEN）

- 真相形态：requirement + scenario 文本（WHEN/THEN/SHALL）。
- 提取配方：一条 scenario 至少一条断言；SHALL 动词枚举成断言动词；负向场景（不得/拒绝）单独成断言；建 requirement↔断言双向索引；规格覆盖度门禁=每条 requirement 被索引或显式 NA。
- 证据手段：既有任务清单的聚焦测试命令（最富证据源）；规格测试（spec tests）；运行时探针。
- 注意：规格常由实现方撰写——角色分离在此塌陷为自洽检查，须核验基准冻结时点（实现开始前的 commit 可证）或由独立会话产出规格。

## 6. API 文档契约（库/SDK 的公共接口承诺）

- 真相形态：rustdoc/jsdoc/OpenAPI/类型定义/CHANGELOG/semver 承诺。
- 提取配方：每个 pub/export 项断言存在性与签名；panic/error 文档行为成断言；弃用标记成断言；semver 断言（破坏性变更须 bump major）。
- 证据手段：类型检查、API 快照测试、doc-test、cargo-semver-checks 类工具。
- 注意：这是纯库项目的**首选基准**（强于冻结现状）；阶段 2 盘点须加库变体（公共 API 面/feature flags/unsafe 块/目标平台）。

## 7. 回归基线（冻结当前行为，遗留系统兜底）

- 真相形态：特征测试/录制快照/黄金文件——**由本方法论现场制造**的基准。
- 提取配方：先定 scope（受变更影响的行为面），再冻结；冻结范围外的行为显式 NA。冻结产物入档 + hash。
- 证据手段：特征测试（characterization tests）、录制回放、黄金文件比对。
- 注意四坑：①成本是开发级不是盘点级，超限即升级或缩范围；②建立**预期偏差登记册**（基线 hash + 显式偏差清单），登记项不计 FAIL 但须独立核验，否则项目有意变更全判 FAIL；③特征测试常只能由实现者写——基线作者独立性须声明为已知折扣；④结词语义漂移：PASS=行为未变 ≠ 正确，报告必须标注。

## 附：按项目形态的基准组合建议

| 形态 | 首选基准 | 常用组合 | 五项视觉检查 |
|---|---|---|---|
| Web/桌面应用 | UI 稿 + 契约图 | + 规格场景 + 架构图 | 启用 |
| 纯后端服务 | 规格场景 | + 契约图 + 架构图 | 检查项级 NA |
| 库/SDK | API 文档契约 | + 规格场景 | 检查项级 NA |
| 移动应用 | UI 稿 | + 契约图 + 设备档位矩阵 | 启用（档位限定） |
| 遗留系统 | 回归基线 | + 逆向规格化出口 | 视产物 |

移动应用附加：阶段 1 声明设备档位矩阵（最小支持/主流/旗舰 × 明暗 × 字体缩放），每轨标注所跑档位，长尾档位默认 T3；就绪定义加"T1 轨具备自动化取证能力"。
