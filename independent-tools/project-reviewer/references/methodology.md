# 完整方法论：要素、证据、轮次、抽样、人工节点

## 一、12 要素（完整定义）

1. **基准真相**：每个检查项锚定一个基准物，基准表记录名称/类别/hash/日期/原始出处/入档路径。外部临时文件（/tmp、剪贴板路径等）先复制入档再算 hash。
2. **基准分类与降级链**：七类（见 extraction.md）。降级优先级：设计图 → 规格场景 → ADR → API 文档契约 → 冻结当前行为（回归基线）。规则：
   - 高级与低级同时存在且**冲突**时，不自动取低级——判 BLOCKED 升级用户裁决（陈旧设计图 vs 新鲜 ADR 是典型）。
   - 四级全无：停下，推荐出口是逆向规格化（如 OpenSpec），最小起步范围由用户圈定；不要硬编检查项。
   - 回归基线级：PASS 只证明"行为未变"，不证明"行为正确"——结项报告必须标注基准层级与认证强度。
3. **检查项原子化**：一条只判一件事。判据可判定 = 可执行命令 / 数值阈值 / 存在性 / 具体行为描述；做不到的标 subjective 进入独立清单（不占 P0-P2、不阻塞结项、唯一出口是用户书面接受）。
4. **分级**：P0/P1/P2/P3 的具体语义由阶段 0 映射表按项目类型定义（防交易域语义硬编码）。域无关底线：P0 至少覆盖"直接导致数据丢失/损坏/安全边界突破"与"核心路径不可用"两条。
5. **判定词表**：见 verdicts.md。
6. **五项视觉检查**（UI 类专用）：字体与层级 / 间距与布局 / 颜色与令牌 / 图标与清晰度 / 文案。逐维记录，观察≠接受。
7. **交互与运行时检查**（UI/流程类必须有）：真实操作序列证据；时序敏感场景（第二次访问、并发、重启后、重连）单列检查项。
8. **状态与尺寸记录**：视口、DPR、数据状态（seed/fixture/真实 + market session 标记如适用）、命令+退出码。**归一化规范**：参考图注明原生像素与密度；并排对照统一到同一 CSS 尺寸；局部对照用等宽等高同密度裁剪。多平台项目须声明设备档位矩阵，PASS 结论限定档位。
9. **对照过程历史**：每轮记录=复测范围 + 结果 + 新增 P0/P1/P2 计数 + "本结论最可能被推翻的 3 种方式"（下一轮强制抽查输入）。历史只追加；结论失效用固定格式："结论失效声明：旧结论 X 因 Y 对范围 Z 失效"。
10. **真实数据原则**：实现截图/演示用真实数据。"预期差异"认定三要素：基准侧数据状态 + 实现侧数据状态 + 差异仅由数据引起的技术原因；只豁免**内容差异**，永不豁免**容器行为**（布局、溢出、截断、状态处理在任何数据量级下都必须成立）。认定记入 track，后续轮次可推翻。
11. **观察不等于接受**：记录性观察与验收结论分离；"用户手动验收通过"是合法证据类型，须记录确认人/时间/范围声明原文，不得由写码会话代填。
12. **收尾门禁**：见 verdicts.md 结项公式。

## 二、证据规范

### 证据三档
| 档位 | 含义 | 适用 |
|---|---|---|
| 真数据 | 产品真实流程在真实依赖下产生 | P0/P2 级问题判据声明的最低档 |
| 录制回放 | fixture/mock server/录制脚本 | 一般检查项；须标注 |
| 构造注入 | 手工插库/一次性脚本造的状态 | 仅辅助；须标注且不得单独支撑 PASS |

引用已有测试作为证据时**必须落到断言级**：检查项 → 测试文件 + 具体断言（行号或用例名）→ 该断言与判据的对应关系。评审方抽查断言内容（断言的是用户可见行为还是中间值）。统计口径为 passed/failed/skipped 分类计数；关联测试被 skip → 该检查项自动 FAIL。

### 可复现的精确定义
从记录的干净状态（fixture/seed hash + 启动命令）经记录的操作序列到达证据状态；复现脚本必须属于被测版本代码，禁止引用门禁范围外的一次性脚本。

### 证据新鲜度
证据须晚于检查项对应代码 rev 产生；track 记录取证时 git rev，冲突以 git 时间戳仲裁。

### 环境纪律
交互取证优先用隔离实例；记录实例标识与清理动作（"验证后关闭实例、临时数据移入废纸篓"式记录）；禁止在开发者活跃实例上做破坏性操作；profile 锁/端口占用类约束写进执行协议。

### 取证采集建议
视觉证据用 Playwright/自动化截图 API 固定 viewport 与 deviceScaleFactor，禁人工截屏（Windows 默认 125% 缩放会引入 DPR 不一致）。API 探针输出带元数据 JSON（时间/URL/命令/退出码/DPR）落 evidence/。**会话制采集**：冷启服务一次，按 run_id 连续采集整批证据，不逐项重启。

## 三、轮次协议

- 轮次文件 `rounds/N.md` 一行制：`| 检查项ID | 状态 | 证据路径 | 判定备注 |`。AI 出草稿，用户只批注。
- 进入下一轮的机器判据：上轮所有 FAIL 的状态 ∈ {fixed(附新证据路径), waived(附豁免编号)}，或触发了新反馈/再基线。口头收尾无效。
- 复测范围 = 受影响项 + 邻近项（同 track 内共享实现组件/状态机/测试文件的检查项；可由脚本从依赖图生成）。
- 止损（按问题计数）：同一问题两轮同样失败 → 升级用户；派生检查项（derived-from 链）继承父项失败计数；拆分/新增检查项动作须用户确认。每 track 硬上限 3 轮，超限 NOT_ACCEPTED 强制结项。
- 总体收敛止损：同一 track 超 5 轮或连续 2 轮新增问题数不降 → 升级用户。
- 汇总防洗白：任何有 FAIL 历史的检查项，终态若为 NA/WAIVED，汇总视图必须带指回旧轮 FAIL 的链接并单独清点。

## 四、抽样协议

- 定位声明：抽样是**威慑+连坐触发器，不是统计证明**（n=20 抽 20% 漏检概率约 47%）。结项措辞与之匹配。
- 抽样者：脚本按"轮次号为种子对检查项编号做哈希"决定，样本编号记入 track；**禁止任何会话自选**。
- 分层：T1 证据不复验只验采集过程；T2 抽 20%；T3 按编册注明的抽样率（视觉对照默认 30%）。
- 失败后效（连坐）：抽中 FAIL → 该检查项所在轨整轨降级 UNVERIFIED 全量复验；下轮抽样比例升至 50%，连续两轮干净才回落。发现一份引用证据与实际不符 → 该来源全部外部证据降级不可信、触发全量复验。

## 五、人工节点（4 个，防第 5 轮橡皮图章）

| 节点 | 最小决策模板 |
|---|---|
| BLOCKED 确认 | 一句话环境事实 + 复现尝试记录（命令/报错） |
| NA/再基线确认 | hash 对比或范围条款原文 + 变更理由 + 新旧基准对照（哪些区域改了、为何） |
| 主观接受 | 差距描述 + 接受原文 + 日期 + 确认人 |
| 止损升级 | 问题两轮失败史 + 当前修复方案 + 请求决策的具体问题 |

再基线附加约束：必须用户确认；基准来源独立性声明（禁实现截图为基准）；基准表在 hash 外记语义版本号，NA/失效标注引用语义版本。

## 六、威胁模型（写入每个工程 README）

本套机制防**偷懒与自我证实**（跳过检查、引用空洞测试、形式独立实质趋同的评审），不防**蓄意导演式造假**（构造状态、预选采集路径、改靶基准）。单人+同机+同源模型环境下存在结构性盲区：P0 检查项建议异构模型评审，或显式记录"本轮评审模型与实现模型同源"作为置信度折扣；评审会话执行前强制输出怀疑清单（"该实现最可能在哪里撒谎/我最可能漏看什么"）。

## 七、与外部任务体系的关系

存在 OpenSpec tasks.md 等体系时：reviewer track 是唯一验收状态源；外部勾选须引用 track 判定 ID；两体系冲突以 track 为准并结项声明中列出冲突项。reviewer 工程定位为该任务体系的执行细化载体（轨道映射回任务编号），不建立第二份任务状态。
