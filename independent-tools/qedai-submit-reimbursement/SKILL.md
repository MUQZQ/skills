# 登记 AI 费用报销

目标页面：https://qedai.df2cloud.com:60008/patodo/outer-ai-usage

## 入口与任务含义

优先直接调用网站自身的业务接口，复用已登录浏览器的同源会话；页面用于确认登录、最终核对和截图，接口不可用时再使用表单。接口地址、参数、事务保存和核对步骤见 [references/api-workflow.md](references/api-workflow.md)，执行录入前阅读。不要导出或打印 Cookie、密码、令牌，不要把登录凭证、会话信息或真实报销材料写入 skill。

用户说“提交一笔报销”并提供费用材料时，通常先走“订阅记录 → 新增订阅 → 保存订阅”。保存费用、审批通过、标记报销已提交、标记转账是不同动作。不得为了让流程继续而自行审批或标记转账，也不能把保存成功说成财务报销已提交。

若用户明确指定已有报销 ID 并要求“标记提交”，进入下文的已有记录流程。仅要求整理流程或演示时，不创建真实记录。

## 准备与查重

1. 确认页面显示“外部 AI 资源管理”和业务操作入口。登录失效则请用户恢复登录；不要切换到开发模式或修改应用。
2. 从用户提供的说明和材料整理：使用人、发票归属地、用途、供应商、订阅项目、下单时间、开始日期、周期、原价及币种、人民币实付款、有效期，以及三类附件。可选的关联账号和代订阅供应商仅在有依据时填写。
3. 优先通过人员费用查询接口分页获取全部记录，包含已提交、已转账记录。用使用人、供应商、期间、金额和发票号查重；必要时读取已有附件名，识别名称填写错误但实际是同一张发票的记录。若改用列表，勾选“显示已转账记录”，文本和日期输入后查询，并检查所有分页。
4. 同一使用人、项目、期间、金额出现匹配记录时，核对是否同一笔费用。已有记录优先报告其 ID 和状态；信息不足以区分时询问用户，不重复新增。
5. 材料与说明冲突、金额或用途不明确时集中询问缺失项。不要把当前日期、默认使用人或示例金额当成真实费用信息。

## 新增记录

### 先核对实际票面

“发票归属地”是登记字段，可能填写错误，不能代替票面核查。打开实际 PDF 或图片，查看购买方名称或 Bill to；必要时提取文字并查看页面图像。按公司抬头核对所属主体，不根据使用人、文件名、个人地址或默认选项推定。个人账单没有公司抬头时明确说明无法据此确认公司归属；用户明确指定的费用归属与票面抬头应分别记录，不把指定归属描述成票面事实。两者冲突且影响本次填写时，先向用户说明并确认。

区分国内电子/增值税发票、境外 Invoice/Receipt、个人账单和支付截图。境外收据即使 Bill to 写了国内公司，也不能称为国内增值税发票。国内发票以购买方判断归属，不以销售方所在地判断。同一笔的多份凭证出现不同公司抬头时单独标注，不自动选一个；Invoice 与配套 Receipt 不重复算作两笔费用。附件分类中有文件只表示该类别非空，不代表已经确认内容完整、有效或可报销。

根据材料构造接口参数；只有接口不可用时才点击“新增订阅”填写表单。2026-11-13 验证时的字段如下，后续以实际接口和页面为准：

| 字段 | 填写要点 |
| --- | --- |
| 使用人 | 自由填写的展示名称，不决定记录账号权限；核对预填值 |
| 发票归属地 | 核对所属主体，不能直接沿用默认“深圳QYF” |
| 用途 | 必填，从当前选项中选择匹配用途 |
| 关联账号 | 可选，仅建立费用与账号的关联，不需要获取账号密码 |
| 下单时间、订阅开始时间 | 按订单和实际订阅信息填写 |
| 供应商、订阅项目 | 按实际购买内容填写 |
| 代订阅供应商、国外订阅 | 有相应事实时填写或勾选 |
| 订阅周期 | 月付、季付、半年付、年付、一次性或自定义；自定义时读取新增字段 |
| 原价、原价币种 | 保留原始价格和币种 |
| 实付款 | 固定为人民币 CNY；使用真实人民币扣款金额，不能把美元金额直接填入或自行用实时汇率估算 |
| 权益到期日期 | 开始日期和周期会自动计算；与凭证核对，必要时按实际日期调整 |

API 充值若用户确认没有到期时间，按一次性费用保存，到期日期为 null；用户指定的用量截图可归入有效期凭证，不虚构到期日期。汇总充值在项目名称中注明期间和笔数。缺少精确下单时间时留空，不以录入时间或付款时间冒充下单时间。每次按本次指示确定使用人、用途、归属地，不硬编码上次报销的信息。

不要点击“套用示例”作为真实录入捷径。不要默认使用“复制订阅”；若用户要求复制，逐项核对日期、金额和附件。

## 附件与保存

- 三类标签分别是“发票”“付款截图”“订阅有效期截图”，各自有“选择文件”入口；支持多张图片和 PDF。
- 三类附件在保存时均可选，允许保存后补充；列表的“材料齐全”要求三类都有。因此材料缺失不等于无法保存，但要明确告知缺哪类。
- 上传前确认用户已授权将指定材料上传到此应用。用户明确要求用所给材料在此站报销时，按已有授权执行，不重复请求同样的许可；仅提供文件或要求检查文件不等于授权上传。
- 优先将文件通过 multipart 上传接口逐份上传，保留返回的 key、url；HTTP 201 也是成功。按文件名和类别保存本次上传结果，上传成功后不因后续步骤失败而盲目重传。
- 保存前核对使用人、项目、日期、原价币种、人民币实付、用途和附件。已有明确录入授权且数据完整时，用一个事务创建一笔费用及其所有附件关联，无需另设确认步骤。文件上传本身不在事务内；只有费用与附件关联一起保存成功，才算该笔登记成功。
- 保存只执行一次。若超时或结果不明，先查询同一笔费用是否已生成报销 ID，再决定是否重试，避免重复记录。
- 保存后按返回的新 ID，分别调用费用详情和附件查询，逐项核对字段、文件名、类别、数量及状态；再刷新页面确认记录出现并保存结果截图。报告“已登记费用，当前待审批/页面实际状态”，同时列出缺失材料；不要宣称完成审批、付款或外部财务系统提交。

## 已有记录的“标记提交”

按报销 ID 定位并核对使用人、项目、金额和当前状态。只有用户明确要求更新该记录的报销提交状态，且该动作与事实一致时才操作。已提交的记录不重复操作。

查看时，待审批记录的“标记提交”处于禁用状态。遇到禁用按钮，读取页面提示并说明阻碍；不能自行点击“审批通过”来解锁。此按钮的完整执行过程尚未实测，实际执行时必须读取当前提示或弹窗，确认其含义，操作后验证状态变化。

“生成审批申请邮件”和“导出压缩包”是另外的功能，不属于默认单笔录入流程；用户未要求时不要发送邮件、导出全部费用或进行批量操作。

## 验证范围

2026-11-13 已实际验证：复用登录会话调用查询、上传和事务接口，创建四笔费用及十八份附件关联；费用详情和附件接口回读成功，页面刷新后显示新记录。费用保持待审批、报销未提交；没有验证审批、标记报销提交或转账操作。后续执行仍须查重和回读，不能沿用历史成功结果代替本次核对。
