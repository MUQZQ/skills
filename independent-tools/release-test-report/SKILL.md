# 发布测试报告与正式包冒烟

## 给定材料

取得目标发布分支或标签、版本白名单、发布功能清单、代码特性及责任田。核对标签和分支指向，记录取证时点和当前打包状态。用户给的格式样例只用于版式，其名称、人员、结论、图片和业务内容不进入新报告。材料缺失时写入相应缺口，继续能从现有材料完成的部分。

## 1. 核对发布范围与 PR

1. 逐模块从发布清单、白名单及代码确认本版保留、裁剪和待确认行为。参考功能附件并回查实际选包、启动组合、代码和规格。清单条数、选用包数和预计装入包数分别统计。
2. 为每项功能查找实际进入发布分支或由其基线继承的 PR，记录纳入依据。用户提供的 PR 号用于起查。用固定提交、PR 详情、变更归档或发布配置链接支撑判断。
3. 使用包内的 [PR Helper 取证脚本](scripts/prhelp_evidence.py) 列出轮次并获取正文和原图，也可使用当前项目已有的授权取证工具。参数和输出见 [使用说明](references/使用说明.md)。同一业务场景选最近一轮真正覆盖该场景的评审，保留该轮原始结论，包括失败、受阻和待确认。较新轮次只验证相邻功能时，引用最近的对应轮次，标明提交、环境和适用范围。较早的通过记录可保留为历史背景。
4. 按场景分别记录验证方式、实际结果和来源。历史 PR、包测试、CI、分支归档和正式包实测各用自己的结果口径。缺直接证据、仅有归档、受阻、失败、待确认及不适用均如实标注。附与场景对应的原始截图，保留图号、PR、轮次和证据编号。抽查 PR Helper 正文的登录要求，工作簿明确标注访问限制并保留内嵌截图。

## 2. 补齐冒烟与指派主测

1. 每个发布功能至少对应一条冒烟用例。逐条核对本报告引用的受阻、失败、未完成、待确认场景，把需要实测的行为改成可执行用例。历史构建或环境受阻对应正式包上的受影响行为，并保留原阻塞原因。分支配置差异要有正式包检查和明确结果。
2. 每条用例使用唯一编号，在 `测试证据` 和 `测试自测结论` 双向填写证据与用例编号。用例写明前置环境、真实样本、动作和可独立回读的预期结果。裁剪功能如要求禁止调用，核对当前发行入口及正常调用门禁。仅看菜单不足以验收。
3. 从本版代码责任田按最接近特性选择具体主测人。记录继承、自当前工作流指定或暂定的来源。补测沿用该责任田，协测按需要列入备注。缺负责人时标明需确认，避免把 PR 作者直接当责任人。
4. 正式包未执行的结论填「待执行」。只有当前发布范围确实不适用时才填「不适用」，在实际结果列注明依据。入口意外缺失、权限或环境阻塞应记录实际情况。

## 3. 继承 Excel 版式

复制 [发布测试报告模板.xlsx](assets/发布测试报告模板.xlsx) 后填充。可用包内 [工作簿脚本](scripts/workbook.py) 复制模板并检查填报。需要重建模板时使用 [模板生成脚本](scripts/build_template.mjs)。命令见 [使用说明](references/使用说明.md)。模板是版式源，保留六个工作表、列序、颜色、冻结、筛选、双栏截图和摘要判定公式。工作表作者工具按当前宿主的表格能力选择。模板空白行从原生 Excel 表格内开始填写，增加条目时扩展对应表格、结论下拉与条件格式。跨版本新建报告时从空白模板开始。更新或复核同一份报告时保留已有用例、结果和证据，仅修改本次涉及的内容。

| 工作表 | 内容 |
| --- | --- |
| 发布测试摘要 | 整体判定、版本与取证时点、范围、按模块汇总、优先冒烟事项、状态统计和来源 |
| 发布功能覆盖 | 功能与发布边界、关联 PR、证据与截图、冒烟编号及责任田依据 |
| 测试自测结论 | 主测人、正式包测试步骤、预期、结论、实际结果和证据 |
| PR 证据索引 | PR、纳入依据、轮次、提交、代码及 PR Helper 链接 |
| 测试证据 | 场景、方法、预期、实际结果、状态、来源、冒烟复验编号 |
| 证据截图 | 双栏原图、来源轮次、关联证据和原图链接 |

按实际模块填摘要列 A，扩展模块区时复核合计公式。用例跨模块共用时，根据覆盖表按模块去重核对用例数。按当期内容填写发布元数据和风险。删除未用的截图卡片。图多时延续双栏卡片。用绝对链接和稳定编号做来源回链。对需要登录的链接标注访问条件，验证链接实际到达正确页面或返回原图。用户只要求修改版式时，逐表比较数据、公式、链接和图片。

## 4. 判定与交付

- **最终冒烟使用正式打包流程生成的产物。** 在实际结果列记录测试包版本或来源、真实环境、观察结果和证据。候选包预跑可用于提前发现问题。随包有校验文件时可用于确认下载完整性。后续正式包有小修，记录变更与影响范围，只复测受影响的用例，沿用此前正式包上仍有效的证据。
- **适用冒烟用例全部通过且证据已回填，即判定本次任务整体测试通过。** 有失败或受阻时保留未通过。存在待执行、缺结果或空白结论时保留阶段汇报状态。不适用项需要可复核的发布范围依据。摘要公式按带编号的用例汇总，遇到缺少编号、编号重复或证据未回填时停留在待核对状态。交付前核实每条通过记录确实来自正式打包产物。
- 交付前核对发布功能覆盖、PR 场景与截图对应、非通过证据回链、用例负责人、实际结果和摘要公式。将摘要的历史佐证和正式包本轮结论写清楚。用户要求独立复核时，可按模块与证据、用例与责任人分开检查，汇总后回改并复核工作簿。
