# 产品介绍短片与录屏配音

把用户的录屏做成可理解的短演示。以用户指定的每条/合并时长、加速方式、声音和交付目录为准，不把这次案例的 1 分钟、男声或路径当作通用要求。

## 先按观看任务分流

- **完整教程**：用户要求保留步骤、顺序或只压缩等待时，直接执行下文“确认范围并检查素材”和“先定画面节奏，再定配音时间”。按原片顺序保留必要动作与结果；输出剪辑安排和缺少的素材信息即可。产品介绍片的价值主张、结果优先重排与 CTA 模板不适用，因为观众需要学会完整操作。
- **产品介绍片**：面向潜在用户讲价值与核心功能时，进入下一节，按卖点选择真实结果和必要操作。已指定的必需主题仍要覆盖。
- **局部审看或技术样片**：按用户指定范围检查，区分技术验证与成片表达；无需补齐完整介绍片的叙事结构。

## 产品介绍片策划

用户面向潜在用户或客户介绍产品、讲解产品价值/核心功能或制作宣传演示时，先规划介绍片，再按用户授权进入制作；保留下文现有录屏教程工作流。策划阶段读取 [产品介绍片策划指南](references/product-intro.md)，输出价值主张、主张与证据/镜头映射、分镜和单一行动号召。不要把策划完成说成视频已制作，也不要把可能需要额外工具的动画包装说成现有脚本能力。

介绍片与完整教程按观众任务分流：介绍片优先回答“解决什么问题、为何有价值、如何进一步体验”；教程保留用户要求覆盖的主题、完整步骤和顺序。若用户明确要求必须涵盖多个主题，应将其纳入策划并指出对时长/可读性的影响，不擅自删减。不要默认固定片长、配音、节奏或产品领域。

产品介绍片先选可证明价值的真实结果镜头，再安排必要操作和配置铺垫。每个核心卖点都要能指出“观众在成片哪一刻看到了什么结果”；设置页、未选择状态和进度条只能证明当前步骤，不能替代成功结果。缺少素材时标记待补；技术验证样片不能据此宣布产品介绍片已验收。

正式合成前，按 [镜头卡与成片验收](references/product-intro.md#从镜头卡到成片验收) 核对选段、变化、停留理由和观看尺寸。先渲染包含核心结果、最难读区域和至少一个切换的短样；用户已要求制作时直接执行，不额外增加确认。样片有问题先修改选段/文稿/构图，再扩展全片。

## 确认范围并检查素材

- 区分“每个文件不到一分钟”和“多个文件合成一分钟”。上下文已明确时不要重复询问。
- 已提供本地文件且要求处理时直接推进。保留源文件，输出到独立目录；不需要改动所在代码仓库或启动开发流程。
- 检查时长、分辨率、帧率和音轨；有音轨不代表有可用声音。核对工具可用性，在任务独立虚拟环境安装所需依赖，不改全局环境。
- 先看按时间采样的联系表，再在点击、页面切换、识别完成等关键位置细看。截图变化小可能是等待，也可能是人工核对；不要仅靠像素差自动判定。

## 先定画面节奏，再定配音时间

1. 标出原片的输入、点击、等待、核对结果、保存/上传、最终效果等区间。默认保留完整时间顺序；删减流程须符合用户要求。
2. 用户要求“以加速为主”时，优先压缩等待和重复停留。操作与结果给更多时间，关键点击可保持原速。全片统一倍速只在用户明确接受时使用。
3. 对每段记录原片起止、目标秒数、用途，计算 `倍速 = 原片秒数 / 目标秒数`。总时长留少量余量，例如上限 60 秒可计划 55～59 秒；这只是建议。
4. 用户明确“只压缩等待”时，操作段保持原速。允许操作变速时可先尝试 1～2 倍，较长操作按总时长权衡；等待可能需要 10～40 倍甚至更高。不能为凑时长让所有关键动作一闪而过；约束冲突时说明需删减或增加时长。
5. 用户说“第 22 秒点击时说……”时，默认指当前成片时间。检查实际点击位置，不能只移动语音而忽略画面。调整某段会影响后续时间，重新计算所有锚点。
6. 配音只描述录屏可证实的行为，不能把“保存到本地”说成“上传个人库”，也不能把待执行说成已完成。用户明确修订业务表述时采用其措辞。

## 同一声音与术语发音

- 选定音色后整条视频保持一致，后续修订继续使用同一 voice ID、语速基准和风格。多个视频是否统一声音依用户上下文。
- 英文缩写/代码名需要听实际合成结果，不能因为稿子写成 `Python` 就宣称语音读对了。尤其检查 Python、DRC、产品名等。
- 不要为修正单词而插入另一名英文说话人的音频；本案例已证明这会造成明显换声。
- 优先使用同一音色的发音控制。若服务无音素控制，可分别保留 `text`（正式稿）与 `spoken_text`（合成稿）；例如把 Python 合成为“派森”是普通话近似发音，不是精确英语发音，须试听并如实说明。
- 改发音时重新合成整句，避免字词拼接的音色、韵律突变。缓存必须包含合成文本、音色、语速，不能只按正式文稿缓存，否则可能重用错误音频。
- 若没有听音工具，只能报告音轨存在、音量和时间检查通过；不要声称“已试听且发音正确”。可给用户提供短音频预览。

## 制作与修订

工具不限定。需要本地可重复制作时，读 [脚本与计划格式](references/workflow.md)，使用 `scripts/video_workflow.py`：支持检查/联系表、多素材剪辑、分段变速、静态裁剪与高亮框、正式文稿字幕、同音色 TTS、有限长度 PCM 配音合成与验证。

- TTS 仅上传合成文稿到服务，不上传原始录屏；使用在线服务前遵守用户对内容与网络的限制。没有可用在线服务时采用已有录音或可用本地声音，不冒充原音色。
- 语音独立于视频变速，不随等待画面一起加速。按句安排起止，先试听；脚本默认不允许超过 1.3 倍语音压缩，超出时缩短措辞、调整画面或明确设置。
- 合成音频使用有限长度缓冲，FFmpeg 输出同时设置时长上限和超时。本案例发生过带无限补静音的滤镜管线持续输出巨大 WAV；不是所有环境必然发生，但不能只依赖无限 `apad` 的下游截断。
- 修改配音不重编无关视频画面；改变速计划后缓存按源文件及分段参数失效。只处理用户指定视频。
- 渲染到临时文件，检查通过再替换最终文件；不要在制作未完成时交付旧缓存或半成品。
- 产品介绍片不为填满配音槽而把短暂设置页或等待画面拉慢。先测实际语音长度，再安排必要的结果阅读停留与切换；文稿太长则改稿或换镜头。结果表格、对比或片尾行动指引的留白可以保留，但要能说明观众在读什么。

## 验证与交付

- 分开报告技术检查与成片审看。`verify` 或测试通过只代表工程行为；运行 [audit 成片诊断](references/workflow.md#成片诊断-audit) 定位长静音、慢放及构图疑点，再逐项回看。提示为审看线索，不能自动判定静态结果页无效，也不能因没有提示就宣布效果合格。
- 每条长停留、高亮框和大面积留边都要有具体用途；按实际观看尺寸检查文字、控件和上下文是否可读。产品介绍片须检查产品识别、价值证据、核心功能结果和下一步；局部片段/技术样片与完整介绍片按各自范围验收。
- 核对每条实际时长严格满足上限、视频完整可解码、音轨非静音且无削波，并检查关键点附近画面。文件大小和“存在音轨”不足以证明有声音。
- 检查语句起点、结尾、重叠、术语发音和同一说话人；机器检查不能替代试听判断。
- 用户指定最终目录后，每次修改都更新该目录，不只更新制作目录；比较哈希确认发布的是新成片。
- 最终提供可点击的成片路径和时长，简述本次变动。分享技能只打包技能说明与通用脚本，不夹带录屏、语音缓存、私人路径或虚拟环境。
