# A3 一页纸报告

## 前置条件

- 有一个明确的**问题/改进主题**（问题描述可一句话说清）
- 需要的是**浓缩呈现**（而非展开分析——那是 PDCA/DMAIC 的过程）

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | 必须控制在一页（A3 纸），任何一格超出一页即返工 | 失去"一页看清全局"的核心价值 |
| **R1** | 每格 ≤5 行或 ≤30 字（标题/数据除外），禁止长篇 | 格子变论文，A3 变文档 |
| **R2** | 根因必须先行（用 5 Whys/MECE 输出），禁止直接给对策 | 跳过根因的对策是打地鼠 |
| **R3** | 对策必须可执行（含责任人/时限/验收标准） | 无验收的对策 = 无法闭环 |
| **R4** | 效果必须可量化（目标值 + 当前值），禁止"明显改善"类表述 | 不可量化的效果无法验证 |

## 模板（九格）

```markdown
# A3: {问题标题}

| 1. 背景（为什么做）      | 2. 现状（数据说话）      | 3. 目标（可量化）        |
| {业务背景/触发事件}      | {当前指标值/问题表现}    | {目标值 + 期限}          |
|--------------------------|--------------------------|--------------------------|
| 4. 根因分析（5 Whys/MECE）| 5. 对策（做什么）        | 6. 计划（谁/何时）       |
| {根因链，非现象列表}      | {按根因对应的对策}       | {责任人 + 时限 + 检查点} |
|--------------------------|--------------------------|--------------------------|
| 7. 效果验证              | 8. 复盘（Keep/Problem）  | 9. 后续（标准化/推广）   |
| {目标 vs 实际对比}       | {过程中学到什么}         | {是否固化为流程}        |
```

## 工作流

```
Phase 0: 确认主题 ──▶ 一句话问题陈述（用户确认）
    │
    ▼
Phase 1: 收集现状 ──▶ 当前指标/数据（无数据标注"待采集"）
    │
    ▼
Phase 2: 根因分析 ──▶ 引用 5 Whys / MECE 输出（不现场重新分析）
    │
    ▼
Phase 3: 填写九格 ──▶ 逐格填写，每格 ≤5 行
    │
    ▼
Phase 4: 一页校验 ──▶ 渲染后必须一页；超页则精简
    │
    ▼
Phase 5: 归档 ──▶ 存 docs/a3/ 或知识库，关联 PDCA 循环记录
```

## 实战反例

| Agent 可能产生的想法 | 实际现实 | 违反规则 |
|---------------------|---------|:------:|
| "问题复杂，两页也合理" | 一页是约束，约束逼出本质 | R0 |
| "根因写'流程不规范'就够了" | 不是根因，是现象；必须追问到可行动层 | R2 |
| "对策写'加强培训'即可" | 无责任人无验收 = 空话 | R3 |
| "效果写'显著提升'就很清楚了" | 无法验证的效果 = 没做 | R4 |

## 使用时机建议

- 改进项目收尾：PDCA/DMAIC 跑完后用 A3 呈现全貌
- 月度复盘：一个主题一张 A3，替代长报告
- 事故复盘：A3 + 5 Whys 组合（根因格引用 5 Whys 输出）
