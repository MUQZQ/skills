# Cynefin 问题域分类

## 前置条件

- 用户提出了一个需要方法论分析的问题
- method-router 的常规分类（diagnose/decide/design...）已完成，但路由精度不够
- 或用户主动提出"这个问题很复杂，不知道怎么下手"

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | 先分域再选方法。Complex 域用 Simple 域的方法 = 必然失败 | 方向性错误，所有后续分析作废 |
| **R1** | Chaotic 域禁止分析，必须先行动止损。区分"紧急"和"混沌"——紧急不一定是混沌 | 分析 10 分钟后才发现应该先切流量 |
| **R2** | Disorder 域必须降级为用户选择。Agent 不能替用户判断"属于哪个域" | 方向由 Agent 猜测，30% 概率选错 |
| **R3** | 不替代 method-router，而是在路由前加一层域判断作为分类增强 | 两个元 Skill 争抢入口，用户体验混乱 |

---

## 五个域速查

```
                    因果关系
                清晰 ← → 模糊
          ┌─────────────────────────┐
    有序  │  Simple      Complicated │
          │  原因→结果    原因→结果   │
          │  显而易见     需专家分析   │
          ├─────────────────────────┤
    无序  │  Chaotic      Complex    │
          │  无因果模式   因果可回溯  │
          │  先止血再分析  探测→感知→响应│
          └─────────────────────────┘
```

| 域 | 特征 | 策略 | 适合的 Skill |
|----|------|------|-------------|
| **Simple** 简单 | 因果关系显而易见，答案是已知的 | 感知→分类→响应（套最佳实践） | 不需要 Skill，直接给答案 |
| **Complicated** 繁杂 | 因果关系存在但需要专家分析 | 感知→分析→响应 | **5W2H / 5Whys** |
| **Complex** 复杂 | 因果关系只能事后回溯，无法预测 | 探测→感知→响应（先试验） | **PDCA / OODA / First Principles** |
| **Chaotic** 混沌 | 没有可辨别的因果模式 | 行动→感知→响应（先止血） | **OODA Loop（加速版）** |
| **Disorder** 失序 | 不知道在哪个域 | 拆解为子问题，每个子问题分域 | 降级为用户选择 |

---

## 工作流

```
Phase 0: 判定问题域 ──▶ Simple / Complicated / Complex / Chaotic / Disorder
    │
    ▼
Phase 1: 匹配策略 ──▶ 根据域选择分析策略
    │
    ▼
Phase 2: 路由增强 ──▶ 将域判断结果注入 method-router 路由决策
```

## Phase 0: 判定问题域

**目的**：用 4 个判据将问题归入正确的域。

### 判据矩阵

| 判据 | Simple | Complicated | Complex | Chaotic |
|------|:------:|:-----------:|:-------:|:-------:|
| 你以前见过类似问题吗？ | ✅ 经常 | ✅ 见过 | ❌ 新颖 | ❌ 从未 |
| 原因和结果的关系？ | 一目了然 | 可分析得出 | 只能事后解释 | 无法辨别 |
| 有现成的解决方案吗？ | ✅ 有 SOP | ⚠️ 有多个方案，需要专家判断 | ❌ 需要试验 | ❌ 没有 |
| 行动后能预测结果吗？ | ✅ 完全可预测 | ✅ 大概率可预测 | ❌ 不可预测 | ❌ 完全不可预测 |

### 判定流程

```
开始
  │
  ▼
有现成 SOP 吗？ ──YES──▶ Simple → 直接执行 SOP
  │
  NO
  │
  ▼
需要专家分析但能找出答案？ ──YES──▶ Complicated → 5W2H / 5Whys
  │
  NO
  │
  ▼
需要先行动再观察才能理解？ ──YES──▶ Complex → PDCA / OODA / First Principles
  │
  NO
  │
  ▼
情况完全失控，必须先止血？ ──YES──▶ Chaotic → OODA 加速版
  │
  NO
  │
  ▼
Disorder → 拆解子问题，逐个判定
```

## Phase 1: 匹配策略

### Simple 域策略

```
"已知问题，已知解法"
→ 直接给出最佳实践
→ 不需要任何分析方法论
→ 输出: 问题 + SOP + 参考链接
```

### Complicated 域策略

```
"已知问题类型，但具体原因需要专家分析"
→ 需要分析方法论
→ 有数据: 5W2H（数据驱动深度分析）
→ 无数据: 5 Whys（逻辑追问定位）
→ 输出: 分析报告 → SCQA 格式化
```

### Complex 域策略

```
"新颖问题，因果关系不明确"
→ 需要探索性方法
→ 小步试验: PDCA（Plan-Do-Check-Act）
→ 快速迭代: OODA（Observe-Orient-Decide-Act）
→ 架构重构: First Principles（从零推演）
→ 关键原则: 安全失败（fail-safe），每步可回滚
```

### Chaotic 域策略

```
"完全失控，必须立刻止血"
→ 禁止分析！禁止分析！禁止分析！
→ 第一步: 行动 — 切流量/回滚/重启/降级
→ 第二步: 感知 — 观察行动效果
→ 第三步: 响应 — 调整行动
→ 稳定后: 转为 Complex 域 → 继续排查
```

### Disorder 域策略

```
"无法判断在哪个域"
→ 拆解问题为子问题
→ 每个子问题独立判定域
→ 如果仍无法判断 → 降级为用户选择
```

## Phase 2: 路由增强

**目的**：将 Cynefin 域判断结果注入 method-router，提升路由精度。

### 注入方式

```yaml
# 原来 method-router 的输出
route:
  primary: 5W2H
  chain: [5W2H, SCQA]

# Cynefin 增强后
route:
  cynefin_domain: Complicated
  primary: 5W2H
  chain: [5W2H, SCQA]
  rationale: >
    域判断: Complicated（因果关系可分析，有专家知识可查）
    → 选择 5W2H（数据驱动）而非 OODA（探索性）
    → 如果分析后仍不确定，升级为 Complex 域 → 改用 PDCA 试验
```

### 域→方法映射速查

| Cynefin 域 | 主方法 | 辅助 | 注意事项 |
|------------|--------|------|---------|
| Simple | — | — | 不激活任何方法论，直接给答案 |
| Complicated | 5W2H | SCQA | 有数据时。无数据时用 5Whys |
| Complex | PDCA / OODA | First Principles | 小步试验，不可预测结果 |
| Chaotic | OODA 加速 | Pre-mortem(事后) | ⚡ 禁止分析，先行动 |
| Disorder | 降级 | — | 拆解后逐个判定，或用户选择 |

## 错误处理

| 环节 | 失败条件 | 处理方式 |
|------|---------|---------|
| Phase 0 | 4 个判据有 2 个以上无法确定 | 标注不确定性，保守选择更无序的域（宁可高估复杂度） |
| Phase 0 | 判据矛盾（见过类似问题但无现成方案） | 拆解为子问题，每个子问题独立判定 |
| Phase 1 | Chaotic 域但用户要求分析 | 坚持 R1：先行动再分析。解释为什么不能先分析 |
| Phase 2 | 域判定与 method-router 分类冲突 | Cynefin 域判定优先于关键词分类 |

> **核心价值**：Cynefin 不是一个分析方法，而是一个"选方法的方法"。它告诉你在拿起 5W2H 之前，先确认 5W2H 是否是正确的工具。
