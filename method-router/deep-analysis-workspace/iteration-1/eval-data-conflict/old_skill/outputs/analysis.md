# 匹配率下降：基于限定事实的分析

## 结论

当前存在报表口径冲突，尚不能断定匹配率真实下降，也不能确定归一化模块是原因。昨天报表为 90/100，今天缓存报表为 45/100，而今天权威服务导出为 90/100。缓存报表虽比权威导出晚 10 分钟生成，但没有记录数据版本，且两份输出没有样本 ID；时间先后不能证明缓存代表更新或同一批数据。现有信息不足以计算下降原因占比、修复成本或 ROI。

## WHAT：已知现象与缺口

| 输出 | 匹配数/分母 | 比率 | 限制 |
|---|---:|---:|---|
| 昨日报表 | 90/100 | 90% | 未提供与今天输出的样本对应关系或版本 |
| 今天缓存报表 | 45/100 | 45% | 未记录数据版本，无样本 ID |
| 今天权威服务导出 | 90/100 | 90% | 无样本 ID，无法与缓存逐条对齐 |

缓存报表相对昨天显示 45 个百分点的差异；但权威服务导出与昨天数字相同。因样本身份、版本和分母口径未能交叉核对，这些数字只能描述各输出，不能据此断言业务匹配率变化或定位根因。没有错误分类明细。

## WHY：待区分原因

目前无法建立有证据的代码级因果链。至少需要区分：缓存数据是否过期或使用了不同版本、两份输出是否覆盖不同样本或分母、以及生成或归一化过程是否造成差异。现有事实不能在这些解释之间作出判断。归一化模块由团队 A 维护是维护归属信息，不是根因证据。

## 如何区分原因

1. 对同一时间窗口重新导出权威结果，并为缓存和权威输出记录数据版本、生成时间、样本 ID 与分母定义。
2. 将两份结果按样本 ID 对齐，先确认样本集合和分母一致，再逐样本比较输入、归一化结果及最终匹配状态。
3. 若样本或版本不同，分别用同一固定样本集和固定版本重跑缓存与权威流程，判断差异是否随数据口径消失。
4. 若固定输入和版本下仍有差异，再逐阶段保存并比较归一化前后值及匹配输出；只有差异首次出现的阶段才是后续定位对象。
5. 保留复跑所用版本、样本清单、分母规则和逐项差异，供团队复核。未完成上述对照前，不直接修改归一化模块。

## WHERE / WHEN

当前没有代码文件、行号、错误时序或错误分类数据，无法精确定位。已知缓存报表比权威导出晚 10 分钟生成；这仅是时间顺序，不足以推出数据依赖或因果关系。应先补齐版本和样本追踪，再按生成链路定位差异首次出现的位置。

## WHO：责任边界

| 事项 | 已知信息 | 当前可确认的责任 |
|---|---|---|
| 归一化模块 | 由团队 A 维护 | 可作为差异验证后的调查协作者，尚无证据归责 |
| 最近提交 | 只改按钮文字 | 无证据关联报表数据差异，不能认定提交者为原因或责任人 |
| 缓存与权威导出的版本、样本、分母记录 | 事实中缺失 | 需由掌握相应生成与导出链路的维护方协同补齐；具体负责人尚不能确定 |

## 优先级与建议

**优先级 1：先核对同样本、同版本和同分母。** 这是区分真实数据变化与报表口径差异所需的首要步骤。为两种输出补充可比对的样本 ID、数据版本和分母说明，并执行上述固定输入对照。

**优先级 2：依据对照结果定位差异阶段。** 若口径一致且差异仍存在，再检查缓存生成、归一化和匹配阶段的逐项输出；再决定是否需要团队 A 修改归一化模块。

**优先级 3：根据证据安排修复。** 当前无法给出可靠的代码修改、效果提升、精确成本、优先级收益或 ROI；也没有数据支持 P0/P1 划分。应在取得对照结果后评估影响范围和实施成本。

## 核心结论

现有数字反映输出之间存在冲突，不能证明匹配率实际下降；首先建立同样本、同版本、同分母的对照，再根据差异首次出现的阶段决定修复方向。
