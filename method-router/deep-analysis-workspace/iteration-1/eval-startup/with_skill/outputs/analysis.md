# 启动卡点分析

## 结论

A 的最后可确认状态是等待 180 秒后仍显示 “Loading plugins”；首次未完成阶段无法进一步定位。该文案同时覆盖资源加载、模块激活和界面挂载，且 A 没有逐模块状态，因此不能据此认定卡在某个模块或阶段。第 193 秒发生超时清理，第 194 秒记录的 `host stopped` 位于清理之后，不能证明它是启动卡点的原因。

探针的结果文件只会在 Agent 创建、工具就绪、技能读取成功之后首次写入。A 没有结果文件只说明缺少这份结果证据，不能推断探针未执行，也不能确定这些前置步骤是否完成。A 未到首页，而模型消息只会在首页就绪后发送，因此模型调用或回答质量不是当前卡点的解释。

安装版 commit X 与本地源码 commit Y 的报错范围不同：X 对所有未激活模块报错，Y 只对必需模块报错。在未核实 A 实际加载构建前，Y 只能作为解释线索，不能代表 A 的行为。B 成功也不能单独定位原因，因为相对 A 同时去掉探针、改用固定调试端口并添加忽略证书参数。

目前没有足够证据确认根因，也没有事实能够排除上述候选或其交互。

## 最小下一步实验

先在 A 的同一运行批次、自动清理发生前增加有界取证：记录实际安装构建/commit、进程及页面身份、逐模块状态、资源加载与挂载进度、运行时错误、网络/证书失败和启动参数，并保存截图。结果文件缺失时同时检查探针日志覆盖及写盘时机，不将其作为阶段状态替代品。取证结束按原有清理流程恢复，不重启含未保存内容的实例。

随后以可恢复的隔离运行做匹配对照：固定安装构建、数据目录、启动参数、端口、证书设置和探针配置，只改变一个变量。优先先验证“探针开/关”这一差异；两组均用相同有界期限和相同阶段采样。若结果没有区分力，再另开一轮，仅改变端口配置；之后如仍有证书线索，再单独比较证书参数。不要在同一轮叠加多个改变。

- **独立成功条件：** 在预先设定的期限内到达首页，并记录模块激活和挂载状态；首页就绪后才发送模型消息。首页前没有模型消息是预期行为，不以模型响应作为启动实验的指标。
- **失败取证：** 到期前后记录最后成功阶段、首个未完成阶段、模块错误、资源/证书/连接错误及实际构建身份；注明采样与清理的时间顺序。若无法观测某项，标为未知。
- **恢复：** 保存证据后按既定流程清理隔离运行，并恢复原启动参数和探针设置；不清空原用户数据。

## 停止条件

每轮只运行一次有界对照；若观察工具未能提供阶段证据，或实际构建/固定条件无法核实，则停止该轮并报告未决，不据此重复同条件尝试。若出现数据风险、实例身份不明或无法安全恢复，立即停止实验，先保留现状与证据。达到预设期限后即取证并结束该轮，不靠延长等待或改变验收门槛制造通过。只有单变量对照得到可重复、能区分候选的结果，或出现直接错误与调用链证据，才提升结论为根因；否则保留候选和未决状态。
