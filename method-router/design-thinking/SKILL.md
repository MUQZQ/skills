# Design Thinking 设计思维

## 前置条件

- 设计对象是**面向使用者**的新系统/新功能/新流程（有真实用户或使用者）
- 需要的是**以用户为中心**的设计（而非从原理推导——那是 First Principles）

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | 共情阶段必须接触真实用户（访谈/观察/数据），禁止凭想象定义需求 | 跳过共情 = 设计自嗨 |
| **R1** | 定义阶段必须输出"用户故事 + 痛点 + 目标"，用户确认后才进构思 | 问题没定义对，方案全是白做 |
| **R2** | 构思阶段发散（量）与收敛（质）分离，禁止边想边评 | 边想边评杀死创意 |
| **R3** | 原型必须最小可测（纸面/线框/最小实现），禁止先做完整版 | 完整版原型 = 不敢推翻 |
| **R4** | 测试必须用真实用户，观察行为而非问"你觉得怎么样" | 用户说的 ≠ 用户做的 |

## 工作流

```
Phase 0: 界定对象 ──▶ 目标用户 + 设计范围（用户确认）
    │
    ▼
Phase 1: 共情 ──▶ 访谈/观察/数据收集（≥3 个真实输入源）
    │
    ▼
Phase 2: 定义 ──▶ 用户故事 + 痛点 + 设计目标（用户确认）
    │
    ▼
Phase 3: 构思 ──▶ 发散（10+ 个方案，不评价）→ 收敛（选 2-3 个）
    │
    ▼
Phase 4: 原型 ──▶ 最小可测原型（纸面/线框/MVP）
    │
    ▼
Phase 5: 测试 ──▶ 真实用户试用 + 行为观察 → 迭代（回 Phase 2 或 3）
    │
    ▼
Phase 6: 输出 ──▶ 设计结论 + 决策记录（建议 ADR 归档）
```

### 共情输入源（至少 3 选）

- 用户访谈（3-5 人，开放式问题）
- 行为数据（日志/埋点/使用记录）
- 现有反馈（投诉/工单/评价）
- 竞品观察（同类产品用户怎么做）

## 实战反例

| Agent 可能产生的想法 | 实际现实 | 违反规则 |
|---------------------|---------|:------:|
| "用户需求我猜一下就行，问太多费时间" | 猜的需求 80% 会返工 | R0 |
| "方案 A 不错，B 太怪了，直接否掉" | 收敛太早，好创意被杀死 | R2 |
| "原型直接做完整功能，一步到位" | 完整版舍不得推翻，试错成本巨大 | R3 |
| "测试就问用户'你觉得好用吗'" | 用户会说好，但行为暴露真相 | R4 |

## 输出模板

```markdown
## 设计结论
- 目标用户：{画像}
- 核心痛点：{…}
- 设计目标：{可验证的目标}
- 选定方案：{…}（构思时的候选：{…}）
- 原型测试：{测试人数 + 关键发现}
- 迭代方向：{下一轮改什么}
```
