# 双环学习（Double-Loop Learning）

## 定位

单环学习：发现问题 → 调整行为（动作层面）。双环学习：进一步质疑
"我们默认的规则/假设/框架"本身是否有问题（认知层面）。相同错误
反复发生，通常是单环只修行为、没动框架——双环让你一层层向上问
"我们为什么这样设定"。

## 适用场景

- 复盘发现"同样的问题第三次出现"
- 行为层面的改进收效甚微（改了动作还在犯）
- 重大方向/规则修正前（改制度、改定义、改衡量方式）
- 用户提到：复盘、还是同样、反复出现、深层原因、假设、思维模式、双环

## 核心步骤

1. **单环先行（快）** — 事件 → 偏差 → 调整行为，先止血
2. **双环追问（深）** — 问两层：
   - "这个偏差背后，我们的什么假设/规则导致了它？"
   - "我们为什么这么设定？支持它的证据还成立吗？"
3. **验证假设** — 证据支持吗？有没有反例？假设有时效吗？
4. **修正框架/规则** — 可能牵涉：制度、定义、衡量方式、禁用规则
   （注意：改框架比改行为影响大，需评估波及）
5. **输出两条线** — 行为修正（快）+ 规则修正（慢），并约定下次
   验证点（周期后看是否复发）

## 示例

**场景**：项目连续三个版本延期。
- 单环：下次排期加缓冲（行为修正）
- 双环：假设"排期大家都报保守" → 追问"为什么报保守"→
  根因：承诺制度惩罚乐观估计 → 框架修正：排期规则改为"双人估算 +
  偏差记录进复盘数据"，而非继续加缓冲

## 边界与互补

| 框架 | 关系 |
|------|------|
| KPT/STAR | 事件复盘（是什么、怎么了）；双环学习（为什么设定这样） |
| OKR | OKR 复盘时若 KR 不达标反复出现，用双环学习检查目标/假设层 |
| PDCA | PDCA 循环多次效果不大时，双环学习是"A 阶段"的深度审计 |

## 输出格式

```markdown
## 双环复盘：{问题}

- 行为修正（单环）：{动作}
- 假设审计（双环）：{我们的假设/规则} ← 证据：{…} ← 还成立吗：{…}
- 规则修正：{新规则/新衡量}
- 验证点：{周期后复查复发}
```

> **核心价值**：重复犯错不是执行力问题，是"规则设计容忍了犯错"。
