# 证据驱动开发方法论(Evidence-Driven Development)

## 适用边界

- 适用:需要"测试→定位→修复→防回退"完整闭环的系统开发/维护;高风险领域(交易/资金/安全)
- 不适用:纯创意输出、一次性脚本、无运行态的文档工作
- 前置:系统可运行(或可启动)、有可查询的状态(数据库/日志/接口)

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | 一切结论挂在可复现证据上;没有证据的判断必须标注"推测" | 结论被推翻,返工 |
| **R1** | P0/P1 级结论至少两个独立来源交叉确认 | 单源误判(实战:复核修正了首判 3 条论据) |
| **R2** | 证据四档可信度递增:代码阅读 < 只读查询 < 自动化测试 < 真实环境实测;重要结论用高档位 | 单测全绿但运行时错误(实战 4 个 P1 全由此发现) |
| **R3** | 没有真实环境实测的修复不算修复 | "修了"但没修好 |
| **R4** | 实现方不得给自己的产出判 PASS;评审由独立会话执行 | 自我证实,问题洗白 |
| **R5** | 根因穷尽候选仍不能闭合时:承认"未闭合",加幂等防线+观察期,不无限追因 | 时间黑洞 |
| **R6** | 遗留问题显式登记(编号+复现命令+修复方向),不假装修完 | 隐性债务累积 |

## 核心流程(五层)

### 1. 测试分层:黑盒→白盒→门禁

```
黑盒探针(真实打运行系统) — 抓"运行时真问题"(最容易漏的单测盲区)
白盒检视(边读代码边测)   — 报错→顺调用链读源码→插桩复现→定位根因
自动化门禁              — 单测+e2e+视觉回归,退出码+分类计数
```

黑盒探针要点:
- **现成工具箱优先(R1)**:探针/取证/截图脚本不先手写——先查 [references/project-bindings.md](references/project-bindings.md) 项目登记表,已登记工具箱直接复用;项目未登记时执行**首次适配**:探明本机/关联仓是否已有现成测试基建,验证可用后登记进表,此后同项目直接查表用,不重复发现、不重写
- 写脚本逐模块覆盖(认证/核心业务/数据读取/写入路径/错误契约)
- 只读优先;写入路径用小额/可清理数据;禁止破坏性操作
- 每个检查点记录 PASS/FAIL + 响应片段,落 JSON 供报告引用
- **对照实验**:同请求改变一个变量(如加过滤条件)隔离问题边界
- 桌面应用(Electron/原生对话框)增量:纯页面内截图(CDP/页内 DOM)看不见被遮挡窗口与原生对话框,取证必须全屏截图;原生对话框可靠交互通道=剪贴板 ^v + UIA Invoke/ValuePattern,SendKeys 直打路径会被中文 IME 拦截转写(实证:路径被转写为「1没pu0」),UIA ValuePattern 在部分现代对话框静默无效——写入后必须回读字段验证;点击前先把应用窗口恢复前台(后台窗口的模态对话框可能被前台锁拦截不显示)

### 2. 根因取证与收口(根因本体路由给 5whys/deep-analysis/fishbone)

本 skill 只补它们不含的两个增量步骤:
1. **先修可诊断性**:日志只有异常类型名时,先加消息+堆栈透传再定位(实战中两次"日志增强后根因自现")
2. **时间线对齐**:多数据源时间戳统一时区语义再比对(UTC/本地裸值混用曾致误判);数据库只读取证(`file:...?mode=ro`);排除法穷尽后仍不闭合→按 R5 幂等防线收口
3. **进程代次对齐(链式多进程架构)**:数据/状态目录放在源码监视范围内,任何数据写入都会被 dev watcher 当源码变更触发受管重启——进程 PID 反复更替是「环境不稳」假象源,数据目录必须移出监视范围;跨进程转发跳(如主进程对话框服务)必须带超时+代际校验,否则重启后代际错位导致请求静默永挂(无错误、无对话框、Promise 永不返回)

### 3. TDD 修复循环

```
红:先写失败测试(锁定预期行为) → 绿:最小实现 → 契约变更同步改旧测试(注明 issue 编号)
```
- 测试是活文档;测试基建缺陷(清理不全串扰)先修基建
- 高频回归路径必须有断言级测试,否则修复无保护
- 生产装配形态用例:测试夹具直接挂载内部组件,而生产装配下该组件被卸载/包裹时用例会假绿(实证:归还焦点的逻辑放在父级卸载的 effect 内,单测全绿但生产永不执行)——每个交互修复必须补一个走生产装配路径的用例

### 4. 防回退:评审工程(细节见 project-reviewer skill)

本 skill 只规定与开发的衔接:
- 修复后由**独立评审会话**复测受影响项+邻近项(角色分离 R4)
- 多轮复核分层:A 符合性逐条 / B 红队反向找茬(专找违规路径) / C 证据级验证(修正 A/B 论据)
- 同源模型环境必须声明"同源折扣"

### 5. 修复策略

| 原则 | 说明 |
|------|------|
| 优先级 = 危害 × 放大效应 | 修复"放大器"(如成本基数)优先,一次修复多路收益 |
| fail-closed 默认 | 未知/取不到 → 拒绝并告警,绝不静默兜底 |
| 防御纵深 | 单点校验会被绕过,关键资金/安全路径层层设防 |
| 事实源唯一 | 派生口径(展示/权重/历史价)不得充当事实源 |
| 幂等防线 | 路径未闭合的异常加候选级二次校验终拦 |

## 收尾闭环(缺一不可)

```
修复 → 门禁全绿 → 重启加载 → 真实复现原缺陷场景(通过)
     → 回写问题追踪(状态/轮次/看板) → 提交(密钥扫描零命中)
```

## 实战反例(全部真实踩坑)

| 反模式 | 后果 | 纠正 |
|--------|------|------|
| 单测直写生产库 | 脏行毒化接口(整表 500) | fixture 强制 tmp_path |
| 实盘脚本混入测试目录 | 跑测试即真实下单 | 立即移出测试目录 |
| 错误契约泛化(500/403 掩盖 detail) | 产线不可诊断 | 稳定错误码透传+关联 ID 落日志 |
| 静默兜底(如行情价充当成本价) | 系统性数据污染 | 唯一事实源+显式告警 |
| 凭单测引用判验收 PASS | 运行时行为不符 | 评审必须自采真实环境证据 |
| 原始成本当决策约束 | LLM 拒绝合理交易 | 沉没成本语义显式澄清 |
| SPA 深链 dev 整页重载后「看似可用」 | 生产打包(无 dev server 源)即脱离应用 | dev 形态实测只算低档证据(R2);深链走受控导航通道并补生产装配用例 |
| 设置界面自动保存成功 ≠ 下游组件已加载 | 设置页填的 API Key 未进提取代理凭据库,运行时报 MISSING_CREDENTIAL | 配置写入与消费面加载是两个证据点,改动后各自验证 |
