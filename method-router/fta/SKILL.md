# 故障树分析（FTA）

## 定位

从"不想要的顶层结果"（顶事件）自上而下追问"哪些事件组合会导致它"，
用逻辑门（AND=必须同时、OR=任一即可）铺开所有触发路径，最后聚焦
最小组合（最小割集）。适合"多个条件同时满足才出事"的复杂失败，
以及事故后的系统性复盘。

## 适用场景

- 事故复盘：已发生的失效，追溯因果逻辑链
- 前置风险：识别"哪些组合能触发系统级失效"
- 与"多因素叠加"类风险相关的评审
- 用户提到：故障树、FTA、失效组合、为什么会同时、顶层风险、事故树

## 核心步骤

1. **定义顶事件** — 唯一的系统级失效（"服务 30 分钟不可用"；
   不要写成"性能差"这类模糊事件）
2. **第一层原因** — 直接导致顶事件的下一层事件（立即原因）
3. **逐层分解到基本事件** — 拆到不可再分/能采集数据/能独立触发
4. **标注逻辑门** — AND（全部发生才触发）/ OR（任一即触发）
5. **化简求最小割集** — 找出"最少数量的基本事件组合"就能导致顶事件的
   集合（高频 / 可防护的优先）
6. **对高概率割集制定对策** — 每一个割集给一个对策或验收约束

## 示例

**顶事件**：周末日报推送失败。
- OR：代理中断 / 数据源凭证失效 / 定时任务未触发
- 代理中断 AND：v2rayN 重启窗口 + API 重试耗尽
- 最小割集：{v2rayN 重启 + 重试策略弱} → 对策：重试退避+容错窗口

## 边界与互补

| 框架 | 关系 |
|------|------|
| FMEA | FMEA 逐环节打分（广度）；FTA 逻辑组合（深度）；先后：FMEA 先列出高风险环节，FTA 对关键的深挖 |
| Pre-mortem | Pre-mortem 找"可能失败"；FTA 把失败的"触发组合"结构化 |

## 输出格式

```markdown
## 故障树：{顶事件}

- 一级原因：...
- 最小割集：
  1. {A + B} → 对策 {…}
  2. {C} → 对策 {…}
```

> **核心价值**：AND 门是救生索——"必须同时"的组合里，只要拆掉
> 一个条件，灾难就不会发生。
