# GTD（Getting Things Done）

## 定位

把"靠大脑记住要做的事"改为"靠系统记住"：大脑只负责想和执行，
不负责记忆。五步流水线让事情从"冒出来"到"被安排"再到"被执行"，
核心收益是减少心智负荷与遗漏。

## 适用场景

- 任务多、碎片化、频繁觉得"还有什么没做"
- 需要管理项目性任务 + 情境性任务（电话/电脑/出门）混合
- 与滴答清单等工具配套（GTD 是方法论，工具是载体）
- 用户提到：事情太多、忘了、脑子乱、收件箱、GTD、整理待办、任务管理

## 核心步骤

1. **收集** — 所有任务/想法（脑内、邮件、消息）全部落入单一收件箱，
   不允许停在"脑子记着"
2. **理清** — 逐个处理：不可行动 → 存档/垃圾桶；可行动：2 分钟内
   能做完 → 立即做；否则 → 委派 / 延迟（写日期）/ 归档到下一步行动
3. **组织** — 分类归位：多步的归"项目清单"、单步的归"情境清单"
   （@电话 / @电脑 / @外出）、要未来的进"等待中"
4. **回顾** — 每周一次：清空收件箱、检视项目与日历、确认下一步行动
   仍然有效
5. **执行** — 按当前情境与可行动性，从清单里取"下一步行动"执行，
   不靠临场想

## 示例

- 收集：公众号文章没写完、灯泡要换、下周二报告、找律师咨询 → 收件箱
- 理清：换灯泡（5 分钟）→ 立即做；找律师 → 委派（家人）；下周二报告 →
  项目清单（多个子步骤）
- 回顾：周日 20 分钟清空收件箱，检视项目进度

## 每日节奏（每日回顾 + MIT 焦点）

GTD 的回顾不只是每周一次。日常节奏建议两班：

- **晨间回顾（组织→执行前）**：与系统对账后选出「今日焦点」，
  遵循 MIT（Most Important Tasks）/「三只青蛙」原则——**硬性 ≤3 条**，
  从下一步行动里挑最重要先做。焦点防的是清单膨胀导致
  「永远完不成 → 对系统失去信任 → 整个弃用」的经典失败模式。
  排序时可按精力曲线匹配：编码/重思考类放精力高峰时段。
- **晚间回顾（打卡化）**：固定三段——今日焦点完成 X/3；
  未完成项滚动到明天并各留一句可能原因；本周完成率一行。
  固定结构与连续记录是节奏得以维持的关键。

**渐进式启动**：初次落地一次只养一个班次（如先晨间回顾），跑稳
再加晚间复盘，最后才是每周回顾。三班一起上 = 系统太重，大概率
几周后被弃用。

**澄清收窄**：不是所有输入都变成任务。只有「指派给我/我必须做」的
真行动项进清单；待决断、待认领、参考类留在收件箱或报告里
（GTD 的 someday/waiting）——否则清单会被无主项撑爆。

## 自动化落地的工程护栏

把 GTD 交给定时任务/脚本执行时，三条工程原则决定系统能否长期运行：

- **快照 diff**：每轮把清单状态写入快照文件，下轮对比后只报告变化
  （新指派/流转/完成/停滞），不做全量倾倒——无状态的每日全量报告
  等于让用户人眼找变化，自动化价值归零。
- **幂等同步**：往工具建任务前先按稳定键（如「[#编号]」前缀）查重，
  存在即更新不新建。没有幂等，重复运行会积累大量重复条目，
  污染清单并摧毁信任。
- **写入边界**：自动化只操作它自己创建的条目（按标签/前缀识别），
  绝不碰用户手建任务；对上游系统（issue/PR 等）保持只读。

## 边界与互补

| 框架 | 关系 |
|------|------|
| Eisenhower/Impact-Effort | GTD 管"不漏"，优先级框架管"先做什么"；GTD 之后用它们排序 |
| 滴答清单 | GTD 是方法论，滴答是工具；既有任务增强技能遵循同一原则 |

## 输出格式

```markdown
## GTD 检视

- 收件箱：{N} 条待处理
- 项目：{N} 个（各 1 个下一步行动）
- 情境今天可执行：{@电脑 3 项 / @出门 1 项}
- 下一步：{第一条可行动项}
```

> **核心价值**：清单的意义不是记下"要做"，而是每件事都有
> "下一步行动"。
