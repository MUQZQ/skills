# Kano 需求特性分类

## 定位

把需求按"满足用户预期的层次"分类：基本型（不做会被抱怨，做了没掌声）、
期望型（做了满意、不做不满，线性收益）、惊喜型（不做无感、做了超预期）。
分类决定"必须做 / 按性价比做 / 有余力再做"，防止把预算花在不痛不痒的地方。

## 适用场景

- 需求池分类：区分"必须"与"锦上添花"
- 产品/功能取舍：有限资源下的差异化权衡
- 满意度调研：理解用户抱怨与惊喜的来源
- 用户提到：需求分类、哪些必做、惊喜点、基本功能、差异化、Kano

## 核心步骤

1. **挑出待评估需求** — 一次 3-5 项，避免问卷疲劳
2. **每项双问**：
   - 正向：如果提供该功能，你的感受是？
   - 反向：如果不提供该功能，你的感受是？
   - 五级：喜欢 / 应该 / 无所谓 / 勉强接受 / 不喜欢
3. **按答法矩阵归类** — 正反组合映射到：基本型 / 期望型 / 惊喜型 /
   无感型 / 逆反型
4. **输出优先级** — 基本型必须做；期望型按投入产出比加权（可配 RICE）；
   惊喜型资源富余再做；逆反型不做

## 示例

**功能候选**：导出 PDF / 深色模式 / 自定义快捷键。
- 导出 PDF：正向"应该"、反向"不喜欢" → 基本型（必须做）
- 自定义快捷键：正向"喜欢"、反向"无所谓" → 惊喜型（后置）
- 深色模式：正向"喜欢"、反向"勉强接受" → 期望型（按性价比安排）

## 边界与互补

| 框架 | 关系 |
|------|------|
| RICE | Kano 定性归类，RICE 量化打分；可前置：Kano 先剔"逆反/无感"，RICE 后排剩余 |
| JTBD | JTBD 找 Job（任务），Kano 判需求层次（满足度） |

## 输出格式

```markdown
## Kano 分类

| 需求 | 正向 | 反向 | 类型 | 动作 |
|------|------|------|------|------|

**行动**：基本 {N} 项×必须；期望 {N} 项×排期；惊喜 {N} 项×后置
```

> **核心价值**：基本型做得再好也不会带来惊喜——资源要花在
> "期望型 ≥ 惊喜型"的配置上。
