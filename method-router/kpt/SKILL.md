# KPT 复盘

## 前置条件

- 有一个**刚结束的周期或事件**（一天/一周/一个任务/一次发布）
- 需要的是**快速 actionable 复盘**（而非深度叙事——那是 STAR）

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | 每个 Problem 必须有对应的 Try（Try 是 Problem 的回应） | 只吐槽不行动 = 无效复盘 |
| **R1** | Try 必须可执行、可验证（下周期能检查是否做了） | 泛泛的 Try 无法闭环 |
| **R2** | Keep/Problem/Try 各 ≤5 条，按影响排序 | 20 条 = 0 条被记住 |
| **R3** | 禁止写"继续努力""加强沟通"类空话，每项必须有具体证据 | 空话复盘浪费 3 分钟 |
| **R4** | 复盘结束必须输出"下周期 1-3 个行动项"（含检查时间） | 不复盘的复盘 = 白做 |

## 模板

```markdown
## KPT 复盘: {周期/事件}（{日期}）

### Keep（继续做，证明有效）
- {做法} — 证据：{具体结果}

### Problem（问题/不顺）
- {问题} — 证据：{具体现象} | 影响：{范围}

### Try（下周期尝试）
- [ ] {可执行动作}（对应 Problem: {#}）— 检查点：{时间}
```

## 工作流

```
Phase 0: 界定周期 ──▶ 复盘对象（今天/本周/这次任务）+ 范围
    │
    ▼
Phase 1: 收集素材 ──▶ 数据/日志/决策链（有量化数据优先引用）
    │
    ▼
Phase 2: 填 K ──▶ 有效的做法（有证据，≤5 条）
    │
    ▼
Phase 3: 填 P ──▶ 问题（现象+影响，≤5 条，按影响排序）
    │
    ▼
Phase 4: 填 T ──▶ 每条 P 至少 1 条 T（可执行可验证）
    │
    ▼
Phase 5: 行动项 ──▶ 提炼 1-3 个下周期行动项 + 检查时间
    │
    ▼
Phase 6: 归档 ──▶ 存入当日记忆/复盘文档（供下周期对照）
```

## 实战反例

| Agent 可能产生的想法 | 实际现实 | 违反规则 |
|---------------------|---------|:------:|
| "今天没成交，Problem 写'市场不好'" | 不是可行动问题；应写"ADX 持续低于门槛，Try=放宽阈值评估" | R0/R3 |
| "Try 写'多观察市场'" | 不可验证；应写"每日 14:00 检查 ATR，连续 3 日 <0.3% 则评估阈值" | R1 |
| "Keep 写 8 条，都很重要" | 超过 5 条 = 没重点 | R2 |
| "复盘完了，行动项下次再说" | 没有行动项的复盘是仪式 | R4 |

## 使用时机建议

- 日T收盘复盘：Keep=今天有效的决策模式，Problem=风控拒绝/信号丢失，Try=次日调整项
- 内容运营：Keep=高赞选题类型，Problem=低互动时段，Try=新选题方向
- 每周五：周 KPT 汇总 + 下周一行动项
