# Pugh 决策矩阵

## 前置条件

- 候选方案 ≥ 2 个（含 1 个基准方案，如"现状/不改变"）
- 需要的是**量化对比排序**（而非单一维度的好坏判断——那是 ADL）

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | 评分标准 ≥ 5 项且必须经用户确认，禁止自行拟标准 | 标准带偏，结论全错 |
| **R1** | 必须有基准方案（通常是现状或最稳妥项），打分是"相对基准"而非绝对值 | 无锚点的分数无意义 |
| **R2** | 打分用离散档位（-1/0/+1 或 1-5），禁止用连续小数制造假精确 | 0.01 的差异被当成真实差距 |
| **R3** | 加权权重必须用户确认，权重合计 = 1（或 100%） | 权重是隐性偏好，不确认就是黑箱 |
| **R4** | 输出必须包含敏感性检查（Top 2 权重变动 ±20% 结论是否翻转） | 单一权重下结论脆弱 |

## 工作流

```
Phase 0: 明确方案 ──▶ 列出候选方案 + 指定基准（用户确认）
    │
    ▼
Phase 1: 定标准 ──▶ ≥5 项评分标准（功能/成本/风险/维护/扩展…）→ 用户确认
    │
    ▼
Phase 2: 定权重 ──▶ 每项标准权重（合计 100%）→ 用户确认
    │
    ▼
Phase 3: 打分 ──▶ 每方案相对基准逐项打分（-1/0/+1 或 1-5）
    │
    ▼
Phase 4: 加权汇总 ──▶ Σ(分数×权重) → 排序 → 标注差距是否显著
    │
    ▼
Phase 5: 敏感性检查 ──▶ Top 2 权重 ±20% 复算，结论是否翻转
    │
    ▼
Phase 6: 输出 ──▶ 结论 + 备选方案理由 + 建议走 ADR 记录
```

### 打分技巧

- -1/0/+1 法：比基准差 / 持平 / 更好——快但粗；1-5 法：更细但易陷入微差纠结
- 差距 < 总分 10% 的两个方案视为"并列"，用非量化因素（团队熟悉度/风险偏好）决出
- 标准中至少包含 1 项"反向标准"（如成本、风险——分数越低越好），防止全正向偏好

## 实战反例

| Agent 可能产生的想法 | 实际现实 | 违反规则 |
|---------------------|---------|:------:|
| "标准我按经验拟 8 条就行" | 标准决定结论，用户不确认 = 替用户做价值判断 | R0 |
| "A 方案 3.2 分，B 方案 3.1 分，A 胜出" | 0.1 分差在打分噪声内，等于随机决策 | R2 |
| "权重按重要性排个序就行" | 排序不等于权重，权重必须显式确认 | R3 |
| "算完了，直接宣布结果" | 权重一变结论就翻，必须先做敏感性检查 | R4 |

## 输出模板

```markdown
## 决策矩阵结果
- 候选方案：A（基准）/ B / C
- 评分标准（权重）：{标准列表}
- 加权总分：A=基准 / B=+X / C=-Y
- 排序：B > A > C
- 敏感性：Top2 权重 ±20% 后排序是否变化 {稳定/翻转，翻转则标注条件}
- 结论：选择 {方案}，理由 {…}
- 后续：建议用 ADR 记录本次决策
```
