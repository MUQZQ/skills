# RICE 评分

## 前置条件

- 候选需求/功能 ≥ 3 个（2 个以内直接用讨论即可）
- 每个候选可估计 4 项参数（至少可粗略估计）

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | Reach/Impact/Confidence/Effort 四项独立估计，禁止合并成"感觉分" | 合并 = 回到拍脑袋 |
| **R1** | Confidence 只用四档：50%（低）/70%（中）/90%（高）/100%（确定） | 连续置信度是伪精确 |
| **R2** | Effort 用统一单位（人日/小时），跨团队必须换算 | 单位不一 = 分数不可比 |
| **R3** | 结果只做排序参考，不单独决定；低 Confidence（<70%）的项标注"待验证" | 把猜测当结论 |
| **R4** | 分数必须可回算（列出 4 项原始值），禁止只给总分 | 不可审计的分数无意义 |

## 公式

```
RICE = (Reach × Impact × Confidence) / Effort
- Reach: 每周期影响人数（用户/请求/交易数）
- Impact: 0.25 微 / 0.5 中 / 1 高 / 2 巨大（或按项目约定档位）
- Confidence: 0.5 / 0.7 / 0.9 / 1.0
- Effort: 人日（统一单位）
```

## 工作流

```
Phase 0: 列候选 ──▶ 需求清单（≥3 项，用户确认范围）
    │
    ▼
Phase 1: 估 4 项 ──▶ 逐项估计 Reach/Impact/Confidence/Effort（附依据）
    │
    ▼
Phase 2: 计算排序 ──▶ RICE 分数 + 排序（保留 4 项原始值）
    │
    ▼
Phase 3: 标注风险 ──▶ Confidence<70% 标注"待验证"；差距 <15% 标注"并列"
    │
    ▼
Phase 4: 决策建议 ──▶ Top 3 建议 + 依据；高 Impact 低 Confidence 的单独提示
```

## 实战反例

| Agent 可能产生的想法 | 实际现实 | 违反规则 |
|---------------------|---------|:------:|
| "Impact 打 0.8 吧，介于中和高之间" | 档位外的数 = 拍脑袋 | R1 |
| "A 用小时算，B 用天算，差不多" | 单位不一直接毁掉可比性 | R2 |
| "Confidence 50% 的项目分最高，就做它" | 低置信度应标注待验证，不做第一优先 | R3 |
| "给用户看总分就行" | 无法回算 = 无法被挑战 | R4 |

## 与 Eisenhower 的分工

| 维度 | Eisenhower | RICE |
|------|-----------|------|
| 定位 | 定性：紧急×重要四象限 | 定量：四参数打分排序 |
| 适用 | 任务级（今天做什么） | 需求/功能级（下个迭代做什么） |
| 输入 | 判断紧急/重要 | 估计 4 项参数 |
