# SBI 反馈模型（情境-行为-影响）

## 定位

把"评价一个人"变成"描述一件事"：只讲可观察的行为与结果，不给性格贴标签。
反馈的阻力通常不是"说错了"，而是"听起来像指责"——SBI 通过三段式消除
人身攻击感，让反馈可被接受、可被执行。

## 适用场景

- 给人（或 Agent）提出改进建议 / 指出问题
- Code Review 评论、协作复盘中的反馈环节
- 辅导、带新人、向上沟通
- 用户提到：反馈、建议、评价、指出问题、怎么说、Review 意见

## 核心步骤

1. **明确反馈目的** — 认可（加强行为）还是改进（修正行为），两者话术不同
2. **S：情境** — 何时何地何事（"昨天下午的发布评审会上"）
3. **B：行为** — 可观察的具体行为，禁止标签化描述（"你总是迟到"❌；
   "会议开始了 10 分钟你才到"✅）
4. **I：影响** — 该行为造成的结果或感受（"错过需求澄清，返工了两天"）
5. **给出建议或请求对话** — 明确下一步（"下次提前 5 分钟确认时间"），
   或开放式提问邀请对方自述
6. **确认理解与下一步** — 复述共识，约定行动

## 示例

- 反馈：上次云服务器迁移（S），你直接删除了旧配置没留备份（B），
  导致回滚时多花 3 小时（I）。下次迁移先导出快照再操作，可以吗？
- 认可：本轮迭代（S），你在提交前主动跑了回归测试并附了结果截图（B），
  评审一次通过、上线零事故（I）。保持这个习惯。

## 边界与互补

| 框架 | 关系 |
|------|------|
| STAR | STAR 是自我汇报（讲自己的事）；SBI 是给别人反馈（讲对方的事） |
| KPT | KPT 复盘产出"问题"，用 SBI 把问题转成对相关人的具体反馈 |

## 输出格式

```markdown
**反馈**：{S 情境}，{B 行为}，{I 影响}。建议：{下一步动作}。
```

> **核心价值**：B 段不发毒——"行为"能描述的事实，才允许出现在反馈里。
