# SCAMPER 创意改造法

## 定位

把"从零想点子"变成"从现有方案做七问"：用七个标准动作扫描已有产品/
流程/方案，每个动作都可能产出改进点。对"不是从零设计，但需要新意"
的场景效率最高。

## 适用场景

- 已有产品/流程/方案需要迭代优化
- 思路枯竭，需要一组"提问清单"启发
- 评审会上现场碰撞改进点
- 用户提到：改进、改造、还能怎么做、变个花样、创新点子、优化方案、SCAMPER

## 核心步骤

1. **定义对象** — 明确要改造的产品/流程/方案（写清当前形态）
2. **逐项七问**（每题产 1-3 个点子，先不筛）：
   - S 替代：哪些成分/材料/工具/环节可以换成别的？
   - C 组合：能和什么合并/混搭/打包？
   - A 适配：能借鉴哪个别的领域的方案？
   - M 修改：放大/缩小/改顺序/改风格能带来什么？
   - P 他用：换个目标用户/用途会怎样？
   - E 消除：去掉一个环节/功能会怎样？（反直觉往往最值钱）
   - R 重排：重排顺序/流程反转/重新分级？
3. **筛选择优** — 用 Impact/Effort 或直觉选 1-2 个下手
4. **试点验证** — 小范围实施验证，再决定推广

## 示例

**对象**：日报流程（每人每天手写发送）。
- E 消除：去掉"每天必发"，改按里程碑事件触发
- C 组合：日报合并到周会材料，一次产出
- R 重排：先小组汇总再向上，减少重复内容

## 边界与互补

| 框架 | 关系 |
|------|------|
| First Principles | FP 从零重建（不保留现有）；SCAMPER 从现有改造（默认保留） |
| Design Thinking | DT 用于新设计流程；SCAMPER 用于存量优化 |
| Impact/Effort | SCAMPER 点子数多时，用它快速筛掉成本高的 |

## 输出格式

```markdown
## SCAMPER 改进清单

| 操作 | 点子 | 价值预估 | 成本预估 |
|------|------|---------|---------|

**推荐试点**：{1-2 个}
```

> **核心价值**：先"消除"再"增加"——删减往往比新增更有价值。
