# SIPOC 流程边界图

## 定位

在分析/优化流程之前，用五分钟画出一页"流程地图"：谁供应、投入什么、
主干几步、产出什么、给谁。它的价值是**框定范围**——很多"流程混乱"
其实是"没共识边界"（做得太宽或太窄），SIPOC 先对齐边界再谈改进。

## 适用场景

- 优化/分析流程前的第一步
- 跨团队沟通流程（A 说"这不归我"，B 说"这不是我上游"）
- 用户提到：流程、边界、上游下游、谁提供、输入输出、梳理流程、SIPOC

## 核心步骤

1. **定流程名称与起止点** — 起什么结束于什么（边界划清）
2. **顾客与产出（Customer / Output）** — 谁消费？交付什么？（先看下游，防止范围反了）
3. **供应商与输入（Supplier / Input）** — 谁提供？需要什么？
4. **主干过程（Process）** — 5-7 个主要步骤（超出说明范围太大，缩或拆）
5. **确认** — 参与者确认边界一致，然后才进改进（PDCA/DMAIC）

## 示例

**流程**：日报生成与推送。
- Supplier：任务调度器、数据源 API
- Input：当日任务数据、市场快照
- Process：取数 → 分析生成 → 审核 → 格式化 → 推送 → 归档
- Output：日报全文 + 知识库归档
- Customer：微信会话用户、周复盘流程

## 边界与互补

| 框架 | 关系 |
|------|------|
| DMAIC | DMAIC/D 阶段可先做 SIPOC 框边界 |
| PDCA | SIPOC 之后再进 PDCA 循环，避免"没弄清边界就改" |

## 输出格式

```markdown
## SIPOC：{流程名}

| Supplier | Input | Process | Output | Customer |
|----------|-------|---------|--------|----------|
| {谁} | {什么} | {5-7 步} | {交付物} | {谁} |
```

> **核心价值**：模糊边界是流程之争的第一来源——SIPOC 先对齐，
> 再谈优化。
