# 六顶思考帽（Six Thinking Hats）

## 定位

结构化讨论框架：把思考拆成六个固定角度（事实/直觉/风险/价值/创意/
控制），一次只戴一顶帽子。避免"你说风险我说价值"的偏执争论——
不是不许反对，而是让每个角度都有被完整表达的机会。

## 适用场景

- 方案评审、技术选型讨论，各方各执一词互不相让
- 团队或多 Agent 协作讨论需要分角色、分角度并行思考
- 头脑风暴、会议需要覆盖全面视角再下结论
- 用户提到：讨论、评审、换个角度、头脑风暴、开会、六顶帽、全面看

## 核心步骤

1. **蓝帽：定义** — 明确主题、目标与议程，宣布帽子顺序（控制帽，
   全流程随时可戴）
2. **白帽：事实** — 只列事实与数据，不含观点、不解释（信息帽）
3. **红帽：直觉** — 表达直觉与感受，不许论证，30 秒即可（情绪帽）
4. **黄帽：价值** — 找积极价值与收益，尽量往好处想（乐观帽）
5. **黑帽：风险** — 列风险与代价，限制时长防止跑偏（谨慎帽）
6. **绿帽：创意** — 提出创意、新方案与替代路径（创造帽）
7. **蓝帽：收敛** — 汇总各帽输出，形成结论与行动计划

## 示例

**主题**：是否引入消息队列解耦订单服务（方案评审）。

| 帽子 | 输出要点 |
|------|---------|
| 白帽 | 订单服务当前 3 个下游依赖；高峰 QPS 5000；现无中间件 |
| 红帽 | 直觉上有点重；换做我会有压力 |
| 黄帽 | 解耦后可独立扩容、故障隔离、后续异步化空间大 |
| 黑帽 | 运维成本、学习成本、单点风险、当前规模可能用不上 |
| 绿帽 | 可先用事件表 + 定时任务模拟解耦，验证后再上中间件 |
| 蓝帽 | 结论：暂不引入，绿帽方案先行，3 个月后复查 |

## 边界与互补

| 框架 | 关系 |
|------|------|
| Pre-mortem | Pre-mortem 是黑帽的深化版（专门找失败路径）；六顶帽做全视角扫描后，可用 Pre-mortem 聚焦黑帽产出 |
| Cynefin | 先用 Cynefin 判断问题域，再用六顶帽组织该域下的讨论 |
| SCQA | 蓝帽收敛结论可衔接 SCQA 输出决策报告 |

## 输出格式

```markdown
## 六顶帽讨论：{主题}

| 帽子 | 结论 |
|------|------|
| 白帽（事实） | {事实与数据} |
| 红帽（直觉） | {直觉与感受} |
| 黄帽（价值） | {收益清单} |
| 黑帽（风险） | {风险清单} |
| 绿帽（创意） | {新方案} |
| 蓝帽（收敛） | {结论 + 行动计划} |
```

> **核心价值**：争论的根源是"把角度当立场"。六顶帽让每个角度
> 轮流完整表达，立场自然松动。红帽发言时不许解释——感受一旦
> 被要求论证，就变成了立场。
