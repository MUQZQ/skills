# Token 管理

以符合验收条件的结果为单位管理成本。预算同时考虑现金、套餐额度、等待时间和返工。先定验收要求，再比较可行方案。

## 核算用量与额度

1. 确认范围是任务、项目还是团队，明确统计周期、时区和实际客户端、网关及供应商。分别记录免费额度及有效期、已购套餐及重置窗口、已用与剩余额度、允许的额外按量支出。读不到时标记未知。
2. Codex 历史用量复用宿主可用的 `codex-token-usage`；Magpie 组、回退和命中经独立工具域调用 `magpie-model-routing`；WorkBuddy、ZCode 等自带权益查对应客户端或供应商的用量和限免页面。仅用量查询或指定网关操作直接走专业工具。
3. 分开报告供应商账单、估算金额、Token 数量和积分。账单与用量按同一实际请求去重；共享套餐只计一次；分清输入、缓存命中与输出口径。产品内限免和 API 定价分别核实。别用历史成功、目录标记或零估价证明当前免费。

## 分配预算与模型

- 小而内聚的任务用主模型直接完成。子任务可独立交付、证据易验收且收益超过交接成本时才委派。用客户端原生子 Agent，给出必要输入、范围和验收条件；主 Agent 负责判断、整合和验收。
- 有 `main` 和 `cheap` 时，主组走套餐→授权的按量兜底；轻量组走已核实的免费→套餐轻模型→主组。零额外支出要求下核对整个回退链，包括嵌套组与供应商回退，确保无按量路径。费用顺序不限制用户明确需要的质量档位。
- ZCode 定时任务的套餐/模型切换交给 `zcode-plan-switch`：先 `--list` 与 `--dry-run`，写入前备份，下一次运行后用 `--history` 核对实际 `provider_id`；活跃会话不支持外部切换。
- 定时巡检、批量证据收集等结果易核对的工作可用轻模型。高风险、反复返工、质量未达标时提升模型或缩小任务范围。独立检视按风险保留必要覆盖，预算不足时报告缺口。若需要整轮分流，先用明确条件；语义分类增加一次模型调用，应把这次成本与误判返工一起计入。

## 交付与复盘

给出当前额度、推荐路线、按量触发条件和升级条件。配置改动、购买额度、创建提醒各按用户授权执行。

有可比数据时，用相近输入和相同验收标准比较首次通过、总耗时、重试、实际命中、套餐消耗和额外支出。没有实测时只给建议及依据。请求更新配置时，交给专业工具并回读，分别报告配置证据与实际请求证据。
