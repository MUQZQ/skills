# Code Review Before Commit

## 职责

本 Skill 只管理提交前的审查模式选择、所选模式的修复循环与提交资格。审查维度、证据状态、快照绑定、独立性及优先级的唯一规则来自 `code-review`；提交范围与 Git 授权继续服从用户请求和目标项目规则。审查完成不代表系统验收通过或新增 Git 授权。

## 触发条件

- 用户请求提交代码时进入本选择闸门，但**不得自动启动 `code-review`**。
- 若用户已明确回复 `1`/“快速”、`2`/“不做”、`3`/“全量”或等价表述，直接采用该模式，不重复询问。
- 若用户未明确模式，提交前只询问一次，必须按固定编号展示：

  **本次提交前 Code Review 请选择：**

  1. 快速
  2. 不做
  3. 全量

  **直接回复 1、2 或 3。**
- 用户只请求审查、未请求提交时，直接使用 `code-review`，不进入本提交工作流。

## 模式定义

| 模式 | 执行内容 | 自动修复与复审 | 问题处理 |
|------|----------|----------------|----------|
| 快速 | 对精确暂存快照执行 1 轮聚焦审查；按变更类型路由必要的语言/领域规则，并检查明显的安全、正确性和回归风险 | 不自动进入修复循环 | 展示 P0/P1/P2；P0 阻止提交，P1/P2 告知后按用户原始提交授权继续 |
| 不做 | 不调用 `code-review`，不创建或更新 `review-issues.md` | 无 | 仅执行提交必需的范围、暂存快照和基础 Git 安全检查 |
| 全量 | 首轮覆盖全部适用维度，后续按 `code-review` 增量复审；最多 5 轮独立审查 | 是，限用户已授权范围 | 最终快照 COMPLETE 且已确认 P0/P1 清零后才具备提交资格；未闭合则停止 |

“快速”是审查深度选择，不得被解释为跳过所有验证；“不做”才表示跳过 Code Review。

## 完成度与提交资格

以下判定依次执行；本表复用 `code-review` 的证据状态和实质缺陷分类，不在此另建证据等级。

| 输入 | 本次动作 |
|---|---|
| 未选模式 | 等待一次模式选择，不审查、不提交 |
| 不做 | 仅执行共同 Git/范围检查及项目另有要求的必要门禁，不伪装成审查通过 |
| 快速或全量，状态 INCOMPLETE | 停止提交，报告必要覆盖/验证缺口、具体待验证高风险项或失效证据 |
| 快速，COMPLETE 且已确认 P0 非零 | 阻断提交；不自动修复，按已有授权或用户后续决定处理 |
| 快速，COMPLETE 且已确认 P0 为零 | 告知 P1/P2 与非阻断未决项，按原始提交授权继续 |
| 快速被阻断后仅获修复授权，S1 尚未独立复审 | 保留原提交阻断，分开报告 S0 审查与 S1 验证；用户明确要求新审查后再恢复判定 |
| 全量，COMPLETE 且已确认 P0/P1 非零 | 剩余轮数和授权允许时修复并复审，否则停止 |
| 全量，最终快照 COMPLETE 且已确认 P0/P1 为零 | 共同检查与项目必要验证通过后，按原始提交授权继续 |

确认缺陷数为零不替代完成度检查。原 P0 实质缺陷不得因重标 P1 而在快速模式放行；风格偏好不冒充实质缺陷。必要证据不足时保留待验证项，不删除记录或降级问题以提交。


## 工作流

1. 读取提交请求，确定提交范围、暂存状态和用户是否已经给出审查模式。
2. 未给出模式时，只询问一次“1. 快速 / 2. 不做 / 3. 全量”，等待用户选择；在选择前不得启动审查或提交。
3. 锁定本次选择。后续即使因修复重新暂存或审查失败，也不再次询问审查模式。
4. 按所选模式执行对应流程。
5. 检查本模式完成度与提交资格，校验最终暂存快照与授权范围一致，确保 `review-issues.md` 未被暂存。
6. 若原始请求已明确授权提交，且提交范围与提交信息可确定，直接提交；不要再增加例行确认。只有范围、提交信息或残留风险需要用户决策时才暂停询问。

## 快速模式

1. 使用 `git diff --cached --name-status` 和 `git diff --cached` 固定本次审查范围；暂存区为空时先按用户授权确定应暂存文件。
2. 调用 `code-review` 的独立主审执行单轮聚焦审查，禁止进入自动修复、自动复审或 5 轮循环。高风险必要验证无法在本轮完成时标记 INCOMPLETE，不暗中升级模式。
3. 先检查 COMPLETE/INCOMPLETE，再输出已确认 P0/P1/P2、待验证项与证据：
   - 有 P0：停止提交，报告阻塞问题并请求用户决定是否修复。
   - COMPLETE 且无 P0：记录 P1/P2 摘要，并按原始提交授权继续。
4. 原快照 S0 为 COMPLETE 且有 P0，或为 INCOMPLETE 时，用户仅追加修复授权可进行修复，并运行与新快照 S1 一致的相关测试和快照检查。分别报告 S0 审查和 S1 修复验证；保留原提交阻断，不把 S1 测试成功改写为独立审查完成。
5. 用户明确要求对 S1 重新审查时，直接按已明确的快速/全量模式执行新的审查请求，不重复索取已给出的授权；新审查满足完成度与门槛后才能恢复提交资格。未要求复审时不自行再跑 Code Review，也不提交；说明需要对 S1 复审的原因和所缺授权。
6. 与审查、验证输入无关的工作树变化不自动使结论失效；仍需证明其不影响目标及必要验证。

## 不做模式

1. 明确记录“用户选择跳过 Code Review”。
2. 不调用 `code-review`，不创建或更新 `review-issues.md`，也不把基础 Git 检查描述成审查完成。
3. 仍检查精确暂存文件、`git diff --cached --check`、提交范围和工作树边界；这些是提交安全检查，不属于 Code Review。
4. 按原始提交授权继续。

## 全量模式

1. 固定目标快照，由未参与本轮实施/修复的主审执行首轮完整审查；后续使用 `code-review` 的增量复审与证据失效规则。
2. 一轮是一次对固定快照完成的独立审查及必要验证，最多 5 轮。确认缺陷后才能在授权范围内修复，相关测试通过并重新暂存后进入下一轮；修改完成先记待复核，不能直接清零。
3. 每轮复核影响路径、未修改消费者与多次修复的组合，更新 `review-issues.md`；最终组合快照须有有效覆盖及项目必要验证。该记录绝不暂存或提交。
4. 最终快照 COMPLETE 且已确认 P0/P1 清零，才结束循环并进入共同检查；第五轮末才完成修复且仍需下一轮复审时，结果为 INCOMPLETE，不执行第六轮、不提交。
5. 有限范围的验证可在本轮预算内补齐；环境或权限缺失、必要工具最终失败、修复越权时立即停止相关动作并报告。连续两轮未关闭任何阻断/高风险待验证项，且没有新增可验证证据时，按无进展提前停止；仅改写报告或重复发现不算进展。
6. 达到 5 轮仍有 P0/P1、必要证据未闭合或验证无法通过时，停止提交并向用户报告，不得用“快速”或“不做”模式自行降级。保留未决项、最后验证快照和继续所需条件。
7. 多 Agent 修复仅在用户或项目规则明确要求委派/并行时使用；同一文件或有依赖的修改保持串行。审查 Agent 默认只读；参与修复者不能复核自己的修复。

## 提交前共同检查

无论选择哪种模式，都要：

- 确认当前仓库、分支、HEAD 和精确暂存文件；审查模式下记录 reviewed_tree，紧邻 commit 前重新读取暂存树和 HEAD，与最终验证版本比较。
- 仅暂存用户授权范围，保留工作树中的无关修改。
- 运行 `git diff --cached --check`；审查模式下核实相关运行证据确实对应暂存源码、测试、配置与产物，不能用含未暂存修复的工作树测试代替。
- 确认 `review-issues.md` 未进入暂存区。
- 暂存树、基线或相关验证输入发生变化时先按影响使证据失效并复核；不满足本模式完成条件则停止，不能跳过或暗中追加快速审查轮次。
- 提交后核对提交树与已检查的暂存快照一致；出现快照不一致时停止，不得自动 amend、reset 或 push。

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|----------|
| R0 | 提交请求不得自动开启 Code Review | 用户失去审查深度选择权 |
| R1 | 未明确模式时只询问一次“1. 快速 / 2. 不做 / 3. 全量”，并允许用户直接回复数字 | 重复打断或选择成本过高 |
| R2 | 已明确模式时不得重复询问 | 无意义阻塞提交流程 |
| R3 | “不做”不得伪装成已完成审查 | 证据等级失真 |
| R4 | “快速”只能执行一轮，不得暗中升级为全量循环 | 时间成本超出用户选择 |
| R5 | INCOMPLETE 均不提交；全量模式残留 P0/P1 或最终修复未复审时不得提交 | 阻塞问题或失效证据进入提交历史 |
| R6 | `review-issues.md` 不得暂存或提交 | 过程记录污染 Git 历史 |

## 错误处理

| 情况 | 处理 |
|------|------|
| 用户回复无法映射到三种模式 | 简短澄清一次，只接受 `1`/“快速”、`2`/“不做”、`3`/“全量”或明确等价表述 |
| 暂存区为空或混入无关文件 | 先按授权范围整理或报告，不启动审查 |
| 快速模式发现 P0 | 停止提交，报告问题并请求修复授权 |
| 全量模式到达轮数上限或无进展 | 停止提交，展示未决问题、最后验证快照与缺失证据 |
| 审查工具失败 | 不宣称审查通过并停止提交；保持本次模式不变，只允许重试；重试受 `code-review` 的次数和预算限制，耗尽则报告 INCOMPLETE。改选模式必须由用户明确提出 |
| 提交快照不一致 | 停止，不自动 amend、reset 或 push |
