# 通用 Python 编码规范模板（v1）

> **文档定位**：本文件是 Python 编码规范的**单一权威来源**（独立 skill，git 版本管理），编码与检视两侧均只做关联引用，不做内容复制。

**关联方**：
- **编码侧**：权威 AGENTS.md 的 R8 强制规则（每会话加载，编码时生效）
- **检视侧**：`code-review/lang-python` 审查时强制加载本规范逐条核对
- **变更原则**：规范有任何调整只改本文件；引用方不需要改动（引用即生效）

**与 code-review/lang-python 清单的关系**（冲突仲裁）：
- lang-python 的详细清单（工程单位、文件操作等）为本规范的领域补充，不冲突
- 有冲突时以本规范为准；已知对齐点：日志懒格式化（非 f-string）、命名 snake_case、文件头编码声明不作硬性要求（Python 3 默认 UTF-8）

本页面是一份**去项目化**的通用 Python 编码规范（27 条），可直接作为：
- 任意 Python 仓库 AGENTS.md 的「编码规范」章节
- `~/.codex/AGENTS.md` 或 `~/.claude/CLAUDE.md` 的全局层
- 审查代码时的逐条检查清单（配合 code-review 使用）

## 使用方式

1. **写代码时**：遵守本规范全部条款；与项目已有约定冲突时，以项目 superset 为准（项目缺省项才用本规范补）
2. **配项目规范时**：复制正文，删除与项目无关条目，补充项目特有红线（安全/工具链/检查命令）
3. **审查代码时**：按「四→五→六→七」重点核对（异常/日志/外部数据/安全），其余条款工具化（ruff 已强制）
4. **参数化原则**：条款中的版本/行宽/工具（py312、100、mypy）均为默认值，项目 pyproject.toml 有配置时以项目为准；本规范只约束"必须有"而非"必须用某版本"

## 规范正文

### 一、语言与风格
1. Python 遵循项目支持的最低稳定版本（默认 3.12+），新模块头加 `from __future__ import annotations`
2. 类型注解：新代码必须完整注解（含 `x | None` 语义），公开 API 必须有类型
3. docstring 遵循摘要 + Args/Returns 结构（Google 风格），全项目统一语言
4. 代码、注释、日志、commit 不使用 emoji 字符
5. 布尔变量用 `is_/has_/should_` 前缀，避免单字母变量

### 二、命名
6. 变量/函数 snake_case、类 PascalCase、常量 UPPER_SNAKE
7. 配置类用 @dataclass + 默认值，参数集中管理，禁止魔法值散落

### 三、格式与静态检查（工具强制）
8. ruff format + isort 为准：行宽与 target-version 遵循项目 pyproject.toml（默认 100 / py312）；提交前必须通过 ruff check
9. import 分组：标准库 → 第三方 → 项目内，组内字母序
10. 若项目启用 mypy，类型改动不得新增 mypy 错误

### 四、异常处理（大厂规约精华）
11. 禁止裸 except / except Exception 吞异常：被捕获的异常必须记日志（含上下文）后重抛或返回错误
12. 捕获要具体（TimeoutError/ConnectionError），不许 Exception 兜底
13. 有 try 必有日志，不静默失败——"静默失败"是最贵的 bug 来源
14. 外部调用（网络/DB/文件）必须设超时；失败走显式降级链 + 告警，不用隐式回退

### 五、日志
15. 统一 logging.getLogger(__name__)；懒格式化 "%s", val，禁止 f-string 拼日志
16. 关键事件必有日志：写入/决策/重试/降级/确认
17. 级别语义：DEBUG 细节 / INFO 正常事件 / WARNING 降级重试 / ERROR 失败；禁用 print 调试

### 六、外部数据与并发（华为"外部数据不可信"思维）
18. 所有外部输入（API/网页/配置文件/环境变量）默认不可信：先校验类型、范围、非空再使用
19. 金额用 Decimal，禁止 float 直接比较；JSON 解析用显式字段提取，禁止模糊模式匹配
20. 时间戳统一带时区（存储 UTC、展示本地）；高精度时间戳用 datetime 对象，不用裸整数
21. 长轮询/重试必须带退避 + 熔断；共享状态原子写或加锁

### 七、安全红线
22. 密钥/Token/凭证永不进代码、commit、日志；只走环境变量或 .env（.env 必须入 .gitignore）
23. 提交前自查：无硬编码密钥、无 print 敏感信息；日志输出敏感信息一律脱敏
24. 临时文件/审查记录/中间产物不入 git

### 八、测试与验证
25. 新逻辑必带测试，命名 test_<行为>；断言精确，禁止模糊匹配
26. 行为验证：改动后必须验证真实行为（运行/重启/实测），"文件一致/配置正确"不可信
27. 涉及生产/主分支的提交，先确认再执行
