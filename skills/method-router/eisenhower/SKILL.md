# Eisenhower Matrix 优先级矩阵

## 前置条件

- 有待排序的任务/问题/需求列表（≥ 3 项）
- 用户可以回答"这个任务重要吗""紧急吗"（或 Agent 可从上下文推断）

## 铁律速查

| 规则 | 内容 | 违反后果 |
|------|------|:------:|
| **R0** | 重要 ≠ 紧急。重要 = 对长期目标的影响。紧急 = 时间敏感性 | 混淆后所有高重要低紧急的事都被推迟，战略欠债 |
| **R1** | Do 象限 ≤ 2 项。如果 > 2，说明紧急度标准太松 | 所有事都是 P0，等于没有优先级 |
| **R2** | 必须为 Decide 象限的每项设定截止日期。无日期 = 永远不会做 | 重要不紧急的事永远被紧急不重要的事挤占 |

---

## 四象限速查

```
                    紧 急 度
                 高 ←──────→ 低
          ┌─────────────────────────┐
    高    │  Q1: Do (立即做)         │  Q2: Decide (计划做)      │
          │  危机、截止日期、阻塞     │  战略、学习、预防、建设    │
    重    │  策略: 立即处理           │  策略: 设定截止日期        │
    要    ├─────────────────────────┤
    度    │  Q3: Delegate (委派)     │  Q4: Delete (删除)        │
          │  打断、某些会议、报告     │  消遣、忙碌工作、逃避      │
    低    │  策略: 委派/自动化        │  策略: 停止/忽略           │
          └─────────────────────────┘
```

---

## 工作流

```
Phase 0: 收集任务 ──▶ 列出所有待排序项，给每项一句话描述
    │
    ▼
Phase 1: 逐项判定 ──▶ 对每项问两个问题：重要吗？紧急吗？
    │
    ▼
Phase 2: 归入象限 ──▶ 按 2×2 矩阵归类
    │
    ▼
Phase 3: 输出行动清单 ──▶ 每象限对应一个行动策略
```

## Phase 0: 收集任务

**目的**：穷举所有待排序项。

### 收集方式

| 来源 | 方法 |
|------|------|
| 用户提供 | 直接列出 |
| Git issues | `git log` / issue 列表 |
| 代码 TODO | 搜索 `TODO`/`FIXME`/`HACK` |
| 最近上下文 | 从对话历史中提取未完成的任务 |

### 输出格式

```markdown
## 任务清单 (共 N 项)

| # | 任务 | 来源 | 当前状态 |
|:-:|------|------|:--------:|
| 1 | 修复登录超时 bug | 用户反馈 | 🔴 阻塞 |
| 2 | 重构用户模块 | 代码 TODO | 🟡 规划中 |
| 3 | 写周报 | 日常 | ⏳ 待办 |
```

---

## Phase 1: 逐项判定

**目的**：对每项任务判定重要度和紧急度。

### 判定问题

| 维度 | 判定问题 | 是 → | 否 → |
|------|---------|:---:|:---:|
| **重要？** | 不做这件事，3 个月后有严重后果吗？ | 重要 | 不重要 |
| | 这件事直接贡献于核心目标/OKR 吗？ | 重要 | 不重要 |
| **紧急？** | 明天之前必须完成，否则有直接损失吗？ | 紧急 | 不紧急 |
| | 这件事阻塞了其他人的工作吗？ | 紧急 | 不紧急 |

### 判定示例

| 任务 | 重要？ | 紧急？ | 象限 |
|------|:-----:|:-----:|:----:|
| 登录超时 bug — 50 个用户受影响 | ✅ (用户体验核心) | ✅ (正在发生) | **Q1 Do** |
| 重构用户模块 — 技术债 3 个月 | ✅ (不清会拖慢迭代) | ❌ (现在能用) | **Q2 Decide** |
| 帮同事 review 一个不紧急的 PR | ❌ (不是你负责的模块) | ✅ (他催了 3 次) | **Q3 Delegate** |
| 整理代码注释格式 | ❌ (不影响功能) | ❌ (不着急) | **Q4 Delete** |

---

## Phase 2: 归入象限

**目的**：将所有任务填入四象限矩阵。

### 输出格式

```markdown
## Eisenhower 矩阵

### 🔴 Q1: Do Now (立即做) — {N} 项
| # | 任务 | 理由 | 预计耗时 |
|:-:|------|------|:-------:|
| 1 | {任务} | {为什么紧急+重要} | 2h |

### 🟡 Q2: Decide (计划做) — {N} 项
| # | 任务 | 截止日期 | 理由 |
|:-:|------|:-------:|------|
| 1 | {任务} | 2026-08-01 | {为什么重要} |

### 🔵 Q3: Delegate (委派) — {N} 项
| # | 任务 | 委派给 | 理由 |
|:-:|------|:------:|------|
| 1 | {任务} | {谁} | {为什么不是你做} |

### ⚪ Q4: Delete (删除) — {N} 项
| # | 任务 | 删除理由 |
|:-:|------|---------|
| 1 | {任务} | {为什么不该做} |
```

## Phase 3: 输出行动清单

**目的**：将矩阵转化为可执行的下一步行动。

### 输出格式

```markdown
## 行动清单

### 🚀 今天
- [ ] {Q1 任务 1} — 预计 {耗时}
- [ ] {Q1 任务 2} — 预计 {耗时}

### 📅 本周
- [ ] {Q2 任务 1} — 截止 {日期}
- [ ] {Q2 任务 2} — 截止 {日期}

### 🔄 委派
- [ ] {Q3 任务 1} → @{谁} — 通知已发
- [ ] {Q3 任务 2} → @{谁} — 通知已发

### 🗑️ 删除
- [x] {Q4 任务 1} — 已从待办移除
- [x] {Q4 任务 2} — 已从待办移除

---

**效率提示**: Q2 事项如果不设截止日期，会在 2 周内全部滑入 Q1。
建议每周五 review 一次矩阵。
```

## 错误处理

| 环节 | 失败条件 | 处理方式 |
|------|---------|---------|
| Phase 0 | 用户只提供 1-2 项任务 | 矩阵仍然可用。标注"任务较少，矩阵价值有限" |
| Phase 1 | 某项任务的"重要性"无法判断（不知道对 OKR 的影响） | 标注"⚠️ 重要性待确认"，默认放入 Q2（宁可高估） |
| Phase 1 | 某项同时高重要高紧急但已有 2 项 Q1 | 标注 ⚡ 冲突。Q1 超载 → 逐项问用户"哪项可以等 2 小时" |
| Phase 2 | Q2 象限 > 5 项 | 警告: Q2 超载，建议对 Q2 内部再用一次 Eisenhower 排序 |

> **核心价值**：Eisenhower 矩阵的价值不在于分类——而在于强迫你承认：你不可能做所有事。Q4 的存在是它的灵魂——**有勇气删除，比有勇气开始更重要**。
